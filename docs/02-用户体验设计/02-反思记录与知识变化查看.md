# 反思记录与知识变化查看

## 默认安静，按需展开

Trace 后的反思不强制插入普通聊天，不抢占用户当前工作。用户可以查看本次任务的反思，也可以浏览跨会话的历史反思。

反思记录应说明审查了什么、依据是什么、形成了哪些判断，以及还有哪些不确定性；不要求展示模型全部内部推理。

## 可查看内容

| 内容 | 用户关注的问题 |
|---|---|
| 单次反思 | 分析对象、发现、依据与认识边界 |
| 历史反思 | 多次任务中认识如何变化，有哪些持续未解决的问题 |
| Memory 变化 | 新增、修正、合并或淘汰了什么内容 |
| Skill 知识变化 | 对某项能力的理解、经验或怀疑发生了什么变化 |
| 进化建议 | 是否值得创建或修改能力，相关理由与预期价值是什么 |

反思没有新发现、没有更新 Memory 或没有提出建议均是允许结果，不以空产出制造失败提示。

## 追溯与干预

知识变化可以关联相关记录和原始证据，用户可继续要求 Agent 重新审查。普通、重复或无价值的反思记录可以后续整理；有效知识与原始执行证据保持独立，不因反思记录被整理而一并删除。

只有值得关注的建议主动提醒，其余认识与构想保留在可访问位置。修改反思机制本身的行为规则或执行代码，也沿用正式授权流程。
