# 版本生效、失败与回退

## 保存与正式生效

用户直接编辑或 Agent 授权修改后，不增加重复人工审批，但必须区分保存了修改和正式启用了新能力。

| 情况 | 应有体验 |
|---|---|
| 描述性知识变化 | 可独立更新并查看修订历史，无需每次发布 Skill Version 或重新验证全部代码 |
| 执行代码、Hooks 或行为规则变化 | 在相应授权边界内保存，经过必要检查 |
| 检查通过 | 自动启用正式版本，展示变化与结果 |
| 检查失败 | 保留上一可用版本，展示失败原因 |
| 开发尚未完成 | 普通任务继续使用已正式生效能力 |
| 版本回退 | 可查看历史并恢复旧的正式能力版本 |

已经开始执行的 Tool 不应因版本更新被中途替换。

## 结果必须分清

开发会话展示实际修改、测试结果、正式生效情况和失败部分。保存草稿、生成代码、测试通过与正式启用不是同一状态，界面应反映实际阶段。

问题不成立、价值不足或用户取消时，可以结束活动且不产生新版本。验证中获得的有效认识仍可以保留。

## 回退边界

Skill 的代码、行为规则与正式能力由 Skill 统一版本管理，不另设重复的 Tool 版本系统。

能力回退不会自动回退 Memory、删除 Log 或抹去已发生的验证结果。相关认识若依赖旧版本，需要能追溯当时的适用背景。
