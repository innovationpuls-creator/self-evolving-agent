# 进化建议中心与采纳流程

## 独立建议入口

设立独立进化建议中心，参考原对话提到的 Qoder Skill Evolution Suggestions 的简洁展示方式。这里借鉴交互原则，不据此锁定实现方案。

建议可跨会话保存和查看。用户可以批量忽略、归档，但逐项采纳；被采纳的建议进入独立会话讨论。

## 一条建议应说明什么

- 想改善什么，或希望获得什么新能力。
- 为什么产生这一建议，关联哪些 Trace、Memory 或 Skill。
- 预期价值及当前不确定性。
- 建议创建 Skill、修改 Tool、调整行为指导或采取其他已定义的改进。
- 哪些问题已被观察到，哪些仅为尚待验证的构想。

不把未经验证的建议包装成已经确认的缺陷。新能力建议也可以来自类比和主动探索，无需虚构现有错误。

## 从采纳到开发

1. 用户采纳建议，进入独立会话。
2. 带入建议背景、预期目标与相关证据引用，不一次性注入全部原始日志。
3. Agent 解释当前问题、提出升级或新建能力的原因，与用户讨论目标及验证方向。
4. 用户同意具体修改目标后，Agent 才进行验证、开发与测试。
5. 通过检查后自动生效；失败或价值不成立时如实反馈，允许没有新版本。

采纳建议不等于立即修改正式能力，也不等于无限授权。用户也可以不经建议中心，主动发起能力改进讨论。
