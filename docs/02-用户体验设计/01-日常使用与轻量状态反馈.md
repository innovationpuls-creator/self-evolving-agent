# 日常使用与轻量状态反馈

## 总体体验

日常使用时专注聊天和任务，需要深入观察时再展开执行、反思和知识变化。系统反馈要真实、充分、及时，但不长期占用界面，不建设常驻的大型状态控制台。

## 各状态的反馈

| 状态 | 用户应能感知的内容 |
|---|---|
| 开始任务 | 在当前任务相关位置显示正在执行 |
| 阶段变化 | 轻量更新当前阶段，不打断工作 |
| 后台反思 | 默认安静，允许查看启动、过程记录与结果 |
| 记忆更新 | 可查看发生了什么知识变化 |
| 发现建议 | 进入建议中心，高价值建议轻量提醒 |
| 开发与验证 | 在对应会话展示实际进展与测试结果 |
| 完成 | 明确展示结果及能力是否正式生效 |
| 失败 | 说明失败原因和可采取的操作 |
| 需要决定 | 保留清楚、可再次进入的待处理入口 |

普通过程状态可以自然收起，历史仍可按需查询。完成、失败、授权和能力变更等重要事件不能只存在于一次性通知中，重新连接后仍应可见。

## 展示约束

- 只显示实际运行状态，不虚构进度百分比。
- Agent 自称任务完成不等于 Tool 已通过验证或新版本已生效。
- 用户无需理解所有内部对象、注册流程与运行事件。
- 不将每个内部错误都转成打断式通知；详细错误与诊断信息按需展开。

这些要求适用于聊天、反思、Memory、Skill、建议和开发活动，而非某一个单独页面。
