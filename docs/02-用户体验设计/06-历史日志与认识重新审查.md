# 历史日志与认识重新审查

## 会话内轨迹

会话区域提供“对话 / 轨迹”Tab，共用当前 Session、输入区和停止按钮；草稿、展开、选中及阅读位置按 Session 隔离。历史会话从会话列表进入，取消独立历史日志页面与全局目录。

轨迹按 Session → Trace → Turn → Tool Call 组织，默认展示当前 Pi 分支的概要，详情按需展开。运行过程自动更新；首次打开定位最新记录，处于底部时跟随更新，上滚阅读后暂停。搜索仅覆盖已加载内容。

Memory、Reflection、Evolution 的来源定位对应会话及事件。旧分支保留；受限 Reflection 来源只读查看，不激活普通会话或开放执行与分支操作。原始证据分页读取，缺失记录、上一有效检查点及未持久化嵌套结果明确提示。未采集的指标保持未知。

此决定替代此前“对话内日志与全局日志双入口”方案；后端历史、诊断 API 和 Agent 的三个 Diagnostic Tool 保留，不增加另一套日志系统。

## 用户主动重新审查

用户可以直接质疑某条认识，要求 Agent 查找历史证据并重新评价。Agent 不应默认维护过去结论，也不能只根据此前总结再写一份总结。

重新审查应能：

1. 找到认识的来源、适用背景和相关执行记录。
2. 比较既有判断与新证据。
3. 支持、补充、修正或推翻原判断；证据不足时保留未解决问题。
4. 更新允许自主维护的描述性知识，保留必要修改依据。

重新审查与自动反思互相补充。涉及 Tool、Hooks、新建 Skill 或长期行为规则的实施，仍需用户批准。

## 历史与当前决定

用户回档或改变决策后，旧分支执行记录可以继续保留，但已废弃的项目决定不能继续作为当前要求。普通历史经验也不应被一概删除。

概要与原始内容均遵守敏感信息保护，不因用户打开日志详情或导出而放宽要求。
