# SA-03：Agent 运行环境与客户端协作

## 三个运行边界

| 边界 | 职责 |
|---|---|
| Pi Runtime | 模型调用、Tool 执行、Session 与上下文 |
| 产品运行管理 | 多会话、后台活动、连接、任务状态、资源与权限协调 |
| 客户端 | 对话与管理操作、状态和历史展示 |

Agent 生命周期由 Pi 主机上的运行管理负责，不由页面或客户端窗口持有。所有 Tool 使用 Pi 所在设备的系统、文件与依赖。本地模式同样适用，不要求三层分别部署。

## 会话调度

不同 Session 支持并行、状态独立。同一 Session 的输入沿用 Pi 消息调度，不将多个并发 prompt 请求直接发送给同一忙碌实例。

原对话列出 AgentSession、SessionManager、session.subscribe()、AgentSessionRuntime、steer()、followUp() 与 dispose() 等候选接口。实际版本、可用性、忙碌输入语义与资源释放行为仍需核对。

产品层需要保证：

- 切换会话不自动中止原任务。
- 正常任务、后台反思、能力开发互不阻塞，优先保障日常交互。
- 开发中的修改不能影响正在使用的正式能力。
- 多客户端看到一致状态，避免重复提交。
- 共享可变资源与相同工作目录的竞争被实际考虑，而非以禁止并行替代。

## 独立反思

触发会话不承担反思的消息执行过程。Reflection 使用独立 Agent 活动，可访问原始历史，不污染原会话或改变原任务。

独立活动不预设独立操作系统进程或不同模型。等待中的反思也不要求原 Session 始终处于活动状态。

## 断开与恢复

| 场景 | 行为 |
|---|---|
| 页面关闭或客户端退出 | 主机运行时任务继续，不随连接销毁 Session |
| 断网 | 继续执行，重连恢复实际状态及必要历史事件 |
| Pi 进程退出 | 恢复持久化记录，识别完成、待处理和中断活动 |

Session 恢复不意味着可从中断 Token 或任意 Tool 继续。某操作可能已经产生副作用但未返回，不能盲目重放；无法确认时展示真实中断状态。

完成、失败和待处理事件应可重连查看；状态来自实际执行而非 LLM 模拟文字。

## 技术验证范围

多 AgentSession 并发、共享资源隔离、Extension 生命周期、后台持久化、消息调度及中断恢复边界，均需源码或实验支持。具体机制汇总到 SA-08。
