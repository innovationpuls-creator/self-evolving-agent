# SA-05：Log、Memory 与 Reflection 的数据协作

## 数据职责

| 能力 | 保存内容 | 不承担 |
|---|---|---|
| Pi Session | 原始对话、Tool 执行证据、模型与上下文变化 | 长期知识管理 |
| Diagnostic Log | 执行指标、异常、调用关系和证据引用 | 完整历史的重复副本 |
| Memory | 有长期价值的经验、知识、怀疑与来源 | 完整运行日志 |
| Reflection | 审查记录、判断依据与结果引用 | 底层采集、索引和存储管理 |

这是目标分工。Pi Session 的实际覆盖、Compaction 后的历史访问以及嵌套元数据是否足够，都需要按具体版本验证。

## 轻量诊断与按需取证

诊断围绕执行效率、行为表现和能力使用，提取已有高价值信息。详细信息范围见 RE-04。

诊断可以记录重复调用、耗时和失败恢复等事实，但不直接将某种调用方式判断为错误或浪费。解释与价值判断由 Agent 根据证据完成。

概要、筛选、调用关系和原始内容均可按需访问。Agent 自主决定先读什么，不强制“先诊断再原文”的固定推理流程，也不将全部历史、Memory 和 Skill 注入上下文。

## 原生历史复用的条件

原对话将 Pi Session 视为主要证据源，提出复用其历史树、分支和压缩记录。项目只补充原生缺失且确实影响分析的信息，不另建完整原始日志。

复用以前置敏感信息保护为条件。如果真实凭证已先写入原生 Session，再对新增 Log 脱敏，仍不满足要求。

原生记录是否覆盖 Skill 实际加载、内部 Tool 调用、知识访问与版本关联，不能只凭整体 Session 能力推断。

## 长期知识一致性

认识允许改变，执行事实不能为了符合新判断而被改写。重要认识应尽可能关联原始证据与适用背景，不只保留没有依据的结论。

会话回档不等于外部 Memory 自动回退。必须能辨认知识来自哪个项目、分支或版本背景；废弃决策不能继续成为当前要求，也不能仅按时间选取“最新记忆”解决所有冲突。

## 独立性

关闭 Reflection 不停止 Log/Memory 的正常使用。更换 Memory 扩展不要求重写 Reflection；各能力可以独立改进，不统一成一种存储格式。

原生 Session 前置脱敏和数据覆盖是后续两个关键验证点，不在本阶段选择数据库或具体索引技术。
