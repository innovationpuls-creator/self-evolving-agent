# SA-07：权限、安全与能力变更边界

## 按执行活动限制权限

| 操作 | 正常 Agent | 自动 Reflection | 授权 Evolution |
|---|---|---|---|
| 读历史、Log、Memory、Skill | 按正常访问权限 | 允许 | 允许 |
| 更新描述性知识 | 按任务权限 | 允许区域内可自主更新 | 授权范围内可更新 |
| 创建 Skill、修改长期行为规则 | 需明确授权 | 禁止 | 目标授权范围内允许 |
| 创建或修改 Tool、Hooks | 需明确授权 | 禁止 | 目标授权范围内允许 |
| 编写或运行验证脚本 | 按正常任务权限 | 禁止 | 目标授权范围内允许 |

权限随活动和资源边界生效，不建立单用户产品不需要的 RBAC 或多角色审批。Pi 基础 Tool 不提供普通 Skill 的用户禁用开关，但其调用与资源访问仍受活动权限约束；自动 Reflection 不能借基础 Tool 绕过限制。正常任务保留原有执行能力，不能把 Reflection 限制扩展到所有 Agent 活动。

同一 Skill 内的描述性知识与受保护行为规则可能相邻，不能因为允许写整个 Skill 就让知识更新改变正式规则。

## 真实执行边界

限制需要覆盖基础文件工具、通用命令、Extension Tool、codemode、嵌套调用、脚本、子进程和直接资源访问。

仅隐藏 Tool、拦截某个专用知识写入接口、指定工作目录或提示 Agent 不要修改，都不足以作为完整保护。原对话指出 Extension 与 Pi 进程共享操作系统权限，不能视为天然沙箱。完整产品的严格敏感信息保护与权限隔离依赖满足既定约束的受控运行环境，不能由 Pi Package 安装成功推断已具备；具体实现与 SDK 控制范围仍需验证。

授权限定目标资源与变更范围，不因同意一个能力开发而扩大至无关 Skill。

## 正式能力与开发中代码

正式启用的 Tool 按正常 Tool Calling 使用，不逐次审批。正在开发或修改的代码在受控环境验证，可按目标管理依赖、运行测试，但不能破坏正式环境或接触无关敏感资源。

新版检查通过后才替换正式版本。只隔离 bash 不足以证明整个路径受控，还要检查扩展和其他执行入口。这里不选择 Docker、虚拟机或具体沙箱技术。

## 三个敏感出口

密码、API Key、Token、私钥、身份信息等均纳入默认敏感信息保护范围，适用于以下三个出口。

| 出口 | 保护范围与要求 |
|---|---|
| 持久化 | 原生 Session、Diagnostic Log、Memory、Skill、反思记录、错误信息及自进化开发测试日志不明文保存识别出的敏感信息 |
| 模型请求 | 不将无关密码、Token、私钥等发送给模型 |
| 客户端与导出 | Web、桌面、日志详情、导出及错误报告遵守相同脱敏要求 |

普通代码、文档等非敏感内容可以完整保留。保护应在存储或外发之前完成，不能先落盘再清理。

对于必须经过敏感信息检查的日志、记忆、导出及外发通道，若无法完成必要检查，不得放行未经检查的数据。

原对话提出需同时检查 Tool Result 的 content 与 structuredContent，以及参数、结果、上下文、系统提示和 Tool 声明变化等潜在路径；实际持久化时序与所有出口需要实证核对，不假定一个 Hook 全部覆盖。

授权 Tool 使用 API Key 不等于允许把 Key 写入日志或模型上下文。真实凭证应由授权执行环境使用。

## 验证边界

用模拟凭证检查正常执行、会话恢复、Compaction 和导出，不能使用真实 Key。分别核对 CLI 与 SDK，若只能保护其中一种，必须明确说明。

泄露测试需覆盖常见凭证格式、模拟身份信息、嵌套对象、异常输出、多语言脚本及自进化开发测试日志，并检查必要安全检查无法完成时，未经检查的数据不会被放行。

自动识别不能保证识别所有未知秘密。验收依据是明确出口与针对性泄露测试，不以启用某个脱敏 Hook 作为充分证明。

同时模拟 Reflection 越权修改正式 Tool、Hooks、规则与脚本绕过，受保护内容不得改变。安全、权限和隔离的具体实现仍待 SA-08 的技术验证。
