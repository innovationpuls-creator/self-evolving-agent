# SA-06：Reflection 与 Evolution 的运行协作

## 确定性运行与自主判断

采用事件触发、Agent 自主执行及独立能力管理。程序负责触发、等待、合并、去重、恢复、权限与版本生效；LLM 负责分析证据、形成认识、举一反三、设计方案与授权开发。

| 职责 | 负责什么 | 不负责什么 |
|---|---|---|
| Reflection Trigger | 监听生命周期，安排可靠执行 | 决定思考内容 |
| Reflection Skill | 自主查询、分析、知识更新及建议 | 底层调度与未经授权的正式变更 |
| 建议管理 | 保存建议、依据和用户决定 | 代替实验确认可行性 |
| Evolution Session | 授权后利用 Pi 完成验证开发 | 重写 Agent Loop |

不要求四个独立服务。Memory、Log 和 Skill Runtime 保持独立。

## 反思运行关系

```text
正常任务稳定结束
        │
        ▼
触发管理：30 秒等待、合并、去重与恢复
        │
        ▼
独立 Reflection 活动
        ├── 按需读取 Session / Log / Memory / Skill / 历史反思
        ├── 保存必要反思记录
        ├── 可更新描述性知识
        └── 可提交进化建议
```

原对话将 agent_settled、pi.on() 与独立 AgentSession 列为候选实现，并指出不应在通知事件中继续驱动原会话；实际事件语义和覆盖以技术验证为准。

该图表示运行职责，不规定 Reflection 内部的分析顺序。反思可以审查过去反思，但其结束不会再次自动触发反思；日常不运行验证实验。

## 建议与开发独立

建议可来自普通任务、用户主动检查、自动反思或开发会话，不要求特定 Reflection 实现。

采纳后进入独立讨论，具体目标获批再开发。继续使用原生 Pi Agent，而不是新建另一套 Coding Agent。Agent 自主选择实现、管理依赖与测试，但不能越过授权目标修改无关能力。

检查、生效与回退由确定性运行机制保证。开发不成立或失败，不否定其中有效的认识成果。

## 局部故障与反馈

| 故障 | 预期边界 |
|---|---|
| Reflection 失败 | 普通 Agent 仍可用，实际失败可查 |
| Memory 暂时不可用 | 不连带破坏已有 Tool Calling |
| 建议保存失败 | 分别报告，不误报已成功知识更新也失败 |
| 开发或版本检查失败 | 旧的正式能力继续可用 |
| 反思 Skill 被修改 | 诊断日志仍独立采集 |
| 客户端断开 | 已提交后台活动不因此取消 |

不强制所有成果作为单一事务一同成功。独立保存实际结果，准确反馈失败部分。

## 验收重点

验证独立反思不污染原会话、按需自主分析、普通任务和反思均能提交建议、授权后实际开发，以及非基础能力关闭不连带破坏无关功能。
