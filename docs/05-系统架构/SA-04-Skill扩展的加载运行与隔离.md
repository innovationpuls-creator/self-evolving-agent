# SA-04：Skill 扩展的加载、运行与隔离

## 分开处理加载行为

| 行为 | 设计要求 |
|---|---|
| 发现 Skill | 优先复用 Pi 原生发现机制 |
| 读取知识 | 渐进读取，不一次加载全部资料 |
| 加载 Tool | 通过 Extension 连接到原生 Tool Calling |
| 注册 Hooks | 使用 Pi 原生生命周期语义 |
| 禁用 Skill | 附属可选 Tool 和 Hooks 停止生效 |
| 更新 Skill | 必要检查通过后生效，不破坏已有执行 |
| 卸载 Skill | 移除对应能力，保留必要历史引用 |

知识、Tool 与 Hooks 在管理上属于同一 Skill，但不具有相同加载与更新方式。描述性知识修改不得意外改变执行逻辑或重新初始化整个 Agent。

## 可执行能力与权限

特殊 Skill 可组织多语言脚本，由 Agent 按需发现使用。脚本和 Hooks 都遵守启用状态与授权范围。

Hooks 可能影响消息、工具与上下文，必须匹配原生事件的观察或干预语义。不能因它属于 Skill 就认定其为低权限脚本。

原对话讨论了 direct、codemode、deferred、hidden 暴露方式与 Tool 注销限制；这些候选机制的组合效果仍需验证。禁用要求覆盖直接和间接调用，不以模型列表或前端隐藏作为充分条件。

## 版本一致性

1. 新版检查未通过前，旧的正式版本继续可用。
2. 已开始执行的 Tool 维持原实际版本，不中途替换。
3. 新版失败不覆盖可用版，可查看原因并回退。
4. Tool、脚本、Hooks 和长期指导通过 Skill 统一版本管理。
5. 描述性知识独立修订并保留历史，无需每次发布 Skill Version 或重验全部代码；后续修正不覆盖当时的知识修订与历史关联。
6. 回退不改写 Log，不自动撤销独立 Memory。

## 异常与隔离

文档解析失败只影响相应 Skill；Tool 错误沿用 Pi 处理并记录诊断；Hook 错误按事件性质安全处理，限制影响范围。安全检查失败不得放行未授权能力。

Extension 不作为安全沙箱。执行隔离应复用成熟方案，覆盖所有调用路径；不能只隔离一个 bash 执行器而让其他扩展绕过。

取消订阅和重载不能被假定为可撤销已经开始的事件分发；具体禁用、生效及运行中处理需按原生语义验证。

## 验收与待验证

原生 Pi 与 SDK 集成分别验证：普通兼容、特殊 Tool 实际调用、禁用后的直接/间接不可执行、更新期间版本一致、失败保留旧版、Hook 重载不重复注册及故障影响范围。

同时验证 Agent 能按 Markdown 说明理解和维护能力。执行隔离、动态管理与多个 Session 观察到的能力一致性尚待技术实证。
