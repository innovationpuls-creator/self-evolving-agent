# DM-03：Session、Trace、Log 与 Reflection 的关系

## 对象含义

| 对象 | 定义 |
|---|---|
| Session | Pi 管理的会话、上下文和历史树 |
| Branch | Session 的历史分支，不另建平行分支系统 |
| Trace | 一段完整用户任务的执行经历，可包含多个 Turn、调用和重试 |
| Diagnostic Log | 与执行经历关联的结构化诊断和证据索引 |
| Reflection | 对一次或多次执行经历的审查活动及其记录 |

原对话将 Pi 分支与历史持久化作为复用基础。实际接口和记录覆盖以技术验证为准，不能据此假定所有内部事件已可观察。

## 关联与范围

一个 Session 可以关联多个 Trace；诊断信息定位其 Session、分支和 Trace。一次 Reflection 可以分析多个 Trace，包含其他 Session 的历史。

**触发范围与分析范围不同。** 当前 Trace 可触发反思，但不能限制 Agent 只能分析当前任务。

Reflection 不拥有 Session、Log、Memory 或 Skill，不复制全部相关日志到自己的记录中。

## 生命周期

任务稳定结束后进入 30 秒等待；同一有效分支继续对话时合并待分析内容，待新任务结束后重新计时。主动结束或切换会话可提前触发，详细运行规则见 RE-05。

反思按需查询证据，保存必要记录，可以更新描述性知识或提出建议。反思自身也形成可追溯执行记录，但结束事件不再自动触发反思。

Trace 是业务分析范围，不重新定义 Pi 的底层 Turn 或事件语义。

## 历史与有效性

原始历史说明发生过什么，当前知识说明现阶段相信什么，二者不能混淆。认识变化不改写执行记录。

用户回档后，废弃分支仍可作为历史证据，但其中已撤销的项目决定不能继续作为当前要求。通用经验是否有效需要独立判断，不因所在分支废弃而一概删除。

## 验收约束

验证跨会话多 Trace 分析、分支关联、压缩后原始证据回溯，以及日志与认识的独立变化。会话回档不能混淆有效决策，反思记录可分析但不自循环。
