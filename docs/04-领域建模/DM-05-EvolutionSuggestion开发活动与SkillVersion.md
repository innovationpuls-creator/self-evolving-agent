# DM-05：Evolution Suggestion、开发活动与 Skill Version

## 三个独立对象

| 对象 | 定义 | 生命周期 |
|---|---|---|
| Evolution Suggestion | 值得考虑的能力或行为改进构想 | 可采纳、忽略、归档或保留 |
| Evolution Activity | 一次讨论、授权验证与开发活动 | 可完成、失败、取消或因需求不成立结束 |
| Skill Version | 可正式使用或恢复的能力版本 | 检查后生效，保留必要历史并可回退 |

这些是领域含义，不预设 API 枚举或数据库状态字段。三者有关联，不构成必须一一对应的流水线。

## 建议与活动

建议可来自当前任务、跨会话分析、Memory 或主动探索。建议不必由自动 Reflection 产生，也不意味着一定开发。

采纳建议后进入独立会话，先讨论依据、原因与目标。具体变更获授权后，才进入相应验证和开发。

活动也可以由用户直接发起，一次活动可涉及多个 Skill；验证失败、价值不足或用户取消均可结束，不一定产出正式版本。

## 活动与版本

新版本经过必要检查后正式生效，失败不破坏上一可用版。Tool、Hooks 和长期行为规则通过 Skill 统一管理正式能力版本，不另建 Tool 版本体系。描述性 Knowledge 独立修订并保留历史，不要求每次发布 Skill Version；后续知识修正不改变旧版本当时的正式能力定义和历史关联。

历史执行可关联实际版本；回退不改写 Log、不自动回退 Memory。正常任务与活动可以并行，开发中的变更不能影响正式能力。

## 用户可感知的状态

| 对象 | 用户需要知道 |
|---|---|
| 建议 | 发现什么、为什么值得考虑、是否待处理 |
| 活动 | 当前实际阶段、进展、错误和最终结果 |
| 版本 | 正式生效的是哪版、更新是否成功、是否可回退 |

所有反馈遵循轻量展示：从建议进入开发会话，再查看 Skill 版本，保持连贯；不要求为三个对象各建一个大型页面。重要结果可追溯，不依赖一次性通知。
