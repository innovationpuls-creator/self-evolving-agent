# DM-04：Memory、Knowledge 与 Reflection 的关系

## 知识归属

| 概念 | 职责与归属 |
|---|---|
| Knowledge | 具体认识、经验、判断或怀疑，是内容概念 |
| Memory | 独立于 Session 保存跨任务知识，分 Global 与 Project |
| Skill Knowledge | 保存特定能力的适用范围、局限、经验与怀疑 |
| Reflection | 读取证据、形成或修正知识的一次活动 |
| Log | 独立保存可追溯运行事实，为认识提供依据 |

Knowledge 不构成第三套独立存储中心。与多个 Skill 有关的认识可放入 Memory 并被引用，不要求维护多个副本。

## 生命周期独立

- Reflection 不拥有 Memory。整理反思记录不应连带删除有效知识。
- Memory 引用 Log，不复制完整历史。修正知识不改变原始事实。
- Skill Knowledge 不等于 Instructions。描述性内容可自主修正，长期指令、Tool 与 Hooks 仍受授权保护。
- 描述性知识独立更新并保留修订历史，不要求每次发布 Skill Version，也不重验全部执行代码。

## 知识变化

系统支持新增、补充、确认、修正、合并、淘汰及回溯。Agent 自主决定如何整理，不为每条知识设固定状态机、晋升审批或演化工作流。

当前知识与历史修改可区分，保留必要来源和修正依据。回溯历史 Skill Version 或执行记录时，应能区分当时的能力定义、相关知识修订与后续知识修正；当前知识不能覆盖历史关联，也不能被呈现为当时已有的内容。事实性判断、经验和未经验证的怀疑应能辨认，不规定具体字段或存储格式。

Global 内容可跨项目使用，Project 内容保留项目范围；归属由 Agent 自动判断，用户可调整。作者身份不决定知识权威。

## 分支与适用性

会话回档不天然撤销外部 Memory。知识需能关联来源、适用项目、会话分支和必要的能力版本背景，以识别被撤销决定。

旧分支中的执行事实与仍有价值的通用经验可以保留，已废弃的项目决定不能重新成为当前要求。不能只按写入时间或“存在于 Memory”判断有效性。

## 验收要求

新会话能发现相关知识；新证据能修正 Memory 和 Skill Knowledge；多个 Skill 能共享认识；来源和修改可追溯；回档后不继续沿用废弃决策。
