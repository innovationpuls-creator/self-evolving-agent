# DP-01：产品开发顺序与阶段性交付

## 交付原则

采用纵向增量开发（Vertical Slice Development）。每个阶段都在同一个产品上扩展，形成可以实际运行、使用和验证的版本，不将模块分别完成等同于产品交付。

交付顺序固定目标、依赖和验收，阶段内部由本地 Codex 根据现有代码与验证结果规划。不能为了尽快形成首版而牺牲既定架构、权限或数据安全要求。

## 五个交付里程碑

| 阶段 | 交付目标 | 用户能力与完成要求 |
|---|---|---|
| D1：Agent 基础产品 | Web/Desktop、Pi SDK、Session | 正常使用真实 Agent，管理、保存和恢复会话 |
| D2：能力与知识系统 | Skill、Memory、Diagnostic Log | 管理能力，跨会话积累、修正和检索知识，查询运行证据 |
| D3：自主反思 | Reflection、后台调度、受控执行 | Agent 自主审查经历、更新允许的知识并提出有依据的建议 |
| D4：自主进化 | 建议、授权开发、候选验证、Skill 发布 | Agent 在用户授权后开发新能力，通过必要检查后自动生效 |
| D5：产品化交付 | 完整体验、跨平台、安全、升级与稳定性 | 用户可以可靠安装、长期使用、更新和恢复产品 |

D1 → D2 → D3 → D4 → D5 是连续集成的交付顺序，不是五个独立项目。后续阶段复用已有 Skill、Memory、Log 和 Pi 执行机制。

## 各阶段范围

### D1：可用 Agent

将分散实验整合为正式 TypeScript 产品。使用已验证的 Pi SDK 1.3.0 基线、独立 Agent Host、React Web 和 Electron Desktop，支持真实模型对话、原生 Tool Calling、模型配置、多会话、历史分支、Compaction、安全持久化和恢复。

建立 SQLite 业务数据库、基础认证、连接管理与轻量运行反馈；保留原生 Skill 和必要 Extensions 的使用能力。用户应能安装桌面应用后完成真实任务，关闭窗口后恢复使用；Web 连接同一个 Host。

D1 需要正常交互体验，不以只有 API 或命令行的后端实验交付。完整范围、增量与验收集中见 [DP-03](./DP-03-D1首个可用产品的开发计划.md)。

### D2：能力与长期知识

统一管理普通 Skill 与特殊 Skill，支持安装、启停、编辑、版本查看和回退。基础 Pi Tool 保留原生实现，不提供普通 Skill 的用户禁用开关，实际调用仍受活动权限约束。

采用 SQLite + FTS5 Memory，支持 Global / Project 作用域、来源、修正历史及当前适用性。普通 Agent 从 D2 开始就能自主保存和修正知识，不等待 Reflection 上线。

Diagnostic Log 保存轻量指标与原始证据引用，供 Agent 自主查询，不复制完整 Pi 历史。正式能力版本与描述性知识修订继续分别维护，具体场景见 [DP-04](./DP-04-D2至D5交付依赖与整体验收规划.md#d2能力与知识系统)。

### D3：自主反思

接入既定调度、持久后台任务、独立 Reflection Session、macOS XPC Worker 与受控模型通道，完成真实 Reflection Skill 和产品集成。

系统负责可靠触发、信息访问及真实权限限制；Agent 自主决定分析方向、是否形成认识或建议，不预设固定检查步骤，不要求每次产生结果。日常 Reflection 不执行实验，不修改正式 Tool、Hooks 或长期行为规则。

Windows 的受限 Worker 通过 AppContainer 实测后才能启用相应自动执行能力，隔离不可用时不能退回高权限执行。

### D4：自主进化

提供建议中心及证据、预期价值和未知因素；支持逐项采纳、批量忽略。用户批准目标后，Agent 在独立 Evolution 会话中自主验证、开发和测试，不要求能力创造必须源于一次失败。

用户批准开发目标后，Agent 使用 Pi 原生工具在独立会话/候选工作区中自主开发测试。候选版本通过必要检查后自动发布，无需第二次审批；失败保留或恢复旧版本，既有 Session 保持连续。无强制沙箱前置条件。

### D5：正式交付

完成 Windows/macOS 安装与更新、macOS 正式签名和公证、Windows AppContainer、真实 Provider 与凭证保护、迁移备份恢复、多会话与后台长期稳定性、体验细节、发布包及使用文档。

D5 集中进行发行验收，不用于补齐此前承诺而未完成的功能。各阶段从开发开始就遵守当时适用的安全、可维护性和体验要求。

## 开发协作与完成标准

| 云端设计职责 | 本地 Codex 职责 |
|---|---|
| 确定阶段目标、范围与产品约束 | 检查源码和实验，制定内部实施计划 |
| 明确验收条件，裁决重大设计变化 | 自主实现、集成、测试和修复 |
| 审查实质架构偏离，确认交付 | 提供可运行版本、实际结果与验证证据 |

普通工程问题由本地自主处理；涉及产品要求实质冲突或重要架构变化时再讨论，不逐函数交接。

每阶段完成必须同时满足：

1. 功能完整：承诺的用户场景可以完成。
2. 实际可运行：功能已集成到产品，不只是独立实验。
3. 验证通过：具备必要自动化测试和实际运行证据。

设计阶段完成不代表 D1～D5 已交付。Faux Provider、数据库建表或工具注册成功不能代替真实业务验收。
