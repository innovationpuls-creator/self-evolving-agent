# DP-03：D1 首个可用产品的开发计划

## 目标与完成范围

将已有技术实验整合为可以日常使用的 Pi Agent 产品。React Web 与 Electron Desktop 共享独立 Agent Host；桌面端支持 Windows/macOS，开箱使用不要求用户手动安装 Node.js、Pi CLI 或 Docker。

D1 不开发自主反思和进化系统，保留后续扩展边界。验收关注完整实际使用过程：

打开应用 → 选择模型 → 让真实 Pi Agent 修改项目文件 → 查看 Tool 过程 → 关闭窗口 → 重新连接 → 继续原会话。

| 用户能力 | D1 交付要求 |
|---|---|
| Agent 对话 | 真实 LLM、流式响应、多轮对话和中断 |
| Tool Calling | Pi 原生文件、Shell 等基础 Tool 实际执行 |
| 模型管理 | 配置模型、Provider 和必要推理参数 |
| 会话管理 | 新建、切换、恢复、多会话并行及原生历史分支 |
| 上下文管理 | 复用原生 Compaction |
| Session 持久化 | 加密保存、恢复及 leafId 一致性 |
| Web / Desktop | 浏览器和 Electron 客户端连接同一个独立 Host |
| 运行反馈 | Agent、Tool、错误、任务与连接状态 |
| 基础安全 | 凭证安全保存、客户端认证及敏感信息保护 |

加密保护静态数据，不替代解密后的模型、客户端及导出等使用通道检查。完整规则见 [EQ-02](../07-工程质量设计/EQ-02-安全威胁模型与权限边界验收.md#敏感数据的保存与使用)。

## 四个实施增量

增量用于形成持续可运行的功能，不固定模块开发顺序或文件拆分。

### D1-A：Agent 与客户端

打通 Web / Desktop → Agent Host → Pi SDK → LLM → Tool Calling。

建立 TypeScript Workspace、React Web、Electron Desktop、独立 Host，采用已验证的 Pi SDK 1.3.0 基线；完成真实模型、基础对话、流式输出、原生 Tool Calling、HTTP/WebSocket 及基础访问控制。

复用 Electron + Pi Host 实验，Faux Provider 只作为机制验证与自动测试依据。D1-A 至少完成一次真实模型端到端验证；Host 有独立运行入口，Web 使用不依赖 Electron 窗口。

### D1-B：会话生命周期

完善多 Session 创建、切换与并行、历史分支、Compaction、安全持久化、Host 重启恢复、客户端断线重连及执行状态同步。

复用 TD-05、TD-08、TD-11 的相关成果。Pi Session 是原始历史权威来源，SQLite 不复制一份完整对话历史。恢复不能盲目重放结果未知的外部操作，应保留中断状态及不确定性。

### D1-C：日常使用体验

完成会话列表与历史、输入、停止、继续、Tool 过程、模型配置、错误与恢复操作、运行和连接状态，以及窗口、托盘和后台运行。

遵守既有轻量体验：普通用户主要看到对话和任务过程，详细诊断按需展开，不建设大型调试控制台。

### D1-D：集成验收

| 场景 | 验收标准 |
|---|---|
| 真实模型 | 完成多轮对话及实际 Tool Calling |
| 文件操作 | Pi 原生 Tool 实际修改文件 |
| Session 恢复 | 历史、分支、Compaction 及后续执行正确 |
| 多会话 | 切换与并行不污染彼此状态 |
| 客户端重连 | 已提交对话与重要状态不丢失 |
| Host 重启 | 恢复有效会话，不盲目重放副作用 |
| 凭证保护 | 不明文持久化，不暴露给无关客户端 |
| 桌面生命周期 | 关闭窗口不意外终止 Host |
| Web | 浏览器连接同一个 Host |
| Windows/macOS | 实际目标系统运行关键功能 |

正式签名、公证、自动更新等发行工作属于 D5，但 D1 不能以跨平台打包成功代替实际运行。当前无法验证的平台或功能明确保留为未验证。

远程 Web 完整部署与访问体验可在后续完善；D1 至少支持独立客户端协议，不开放未经认证的远程控制接口。已实现功能具备必要自动化测试。

## 排除项

D1 暂不实现完整 SQLite Memory、自主 Reflection、Evolution Suggestion、Agent 自主开发新 Tool、特殊 Skill 完整版本管理界面、独立 Diagnostic Log 分析系统、生成代码沙箱执行及正式自动更新与发布服务。

原生 Tool、Skill 和必要 Extensions 继续可用，不因缺少管理界面而禁用既有能力。基础 Tool 不设普通 Skill 的用户禁用开关，实际访问仍遵守活动权限。

不提前建设复杂插件框架、分布式服务或独立工作流引擎。

## 正式开发任务说明

以下保留原对话的 D1 开发提示词，作为开发交接内容。具体实现以相关设计的最终有效决定为准。

```markdown
# 开发任务：D1 — 首个可用的 Pi Agent 产品

请基于当前仓库已有的设计文档和技术实验，
正式开发第一个可日常使用的 Agent 产品。

## 产品目标

构建基于 Pi Agent SDK 的通用个人 Agent。

采用 TypeScript 技术栈，支持 React Web
和 Electron Desktop，共享独立的 Agent Host。

桌面端应开箱即用，不要求用户手动安装
Node.js、Pi CLI 或 Docker。

D1 的目标是交付真正可用的 Agent，
不是技术演示或只有界面的原型。

## 工作方式

首先检查现有仓库、docs/ 和 experiments/，
识别已经验证的实现及当前有效技术决策。

优先复用 Pi 原生 SDK、成熟库及现有实验成果。
不重新实现 Agent Loop、Tool Calling、
Session、Compaction 等原生能力。

根据现有项目自主制定合理的实施计划，
分阶段开发、集成、测试和修复。

不必机械遵循固定的文件结构或开发顺序，
但每个阶段都应形成可实际运行的功能。

## D1 功能范围

- 真实 LLM 接入、流式对话与 Tool Calling
- Pi 原生 Tool、Skill 和必要 Extensions
- 模型及 Provider 配置
- 多 Session、历史分支和 Compaction
- Session 加密持久化及恢复
- Web/Desktop 共享 Agent Host
- 客户端重连、任务状态和错误反馈
- 桌面窗口与后台运行
- 必要的认证、凭证保护和安全边界

具体要求以现有正式设计文档为准。

## 技术约束

- Pi SDK 优先采用已验证的 1.3.0 基线
- Session 保留 Pi 原生结构
- 产品业务数据使用 SQLite
- 不重复保存完整 Agent 历史
- 不修改 Pi Core，除非有充分证据证明必要
- 不引入额外的 Agent 框架或工作流引擎
- 安全措施不得破坏真实 Tool 参数
- 不允许未经授权的客户端控制 Agent
- 优先保证代码清晰、复用成熟机制

已有实验属于验证依据，不应直接视为
生产代码，也不应无理由重新实现。

## 暂不开发

Memory、Reflection、自主进化、完整特殊 Skill
管理和正式自动更新属于后续阶段。

不要提前实现这些功能，
但应避免阻碍其正常扩展。

## 完成标准

必须交付可实际运行的 Web/Desktop Agent。

至少验证：
1. 使用真实模型完成多轮对话和 Tool Calling。
2. Session 保存、恢复、分支和 Compaction 正常。
3. 多会话切换及客户端重连正常。
4. 桌面窗口关闭后，Host 按设计继续工作。
5. 凭证、会话数据和客户端访问受到保护。
6. 已实现功能具备必要的自动化测试。

无法在当前环境验证的平台或功能，
明确记录为未验证，不得声称通过。

## 交付要求

提供：
- 可运行的正式产品源码
- 必要的测试与使用说明
- 已完成的功能和对应验证结果
- 尚未解决的问题
- 与原始设计存在的实质差异及原因

一般工程实现由你自主决定。

只有涉及产品目标、核心架构、安全边界
或重大需求变化时，才提出需要裁决的问题。

不要为了追求形式完整而过度设计。
```

## 开发管理与交付

本地 Codex 先核对有效技术决策、源码及实验，自主制定实施计划，持续集成、测试和修复，不再把 D1-A 细分成由云端逐项指挥的函数或文件任务。

交付包括正式源码、必要测试与使用说明、功能和证据、未解决问题及实质设计差异和原因。只有产品目标、核心架构、安全边界或重大需求发生冲突时才提交裁决。

本篇是 D1 开发任务定义，不表示 D1 已完成。后续里程碑继续复用 D1 产品能力，条件见 [DP-04](./DP-04-D2至D5交付依赖与整体验收规划.md)。
