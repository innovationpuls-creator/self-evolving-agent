# DP-02：正式项目结构与开发任务管理

## 工程组织

采用单一 TypeScript Workspace，按职责组织正式代码。保留同一仓库内已有 docs/ 与 experiments/，只在确有共享需求时提取 packages，不预先拆分大量 npm Package 或微服务。

| 逻辑位置 | 职责 |
|---|---|
| apps/host | Node.js + Pi SDK Agent Host，负责 Session、SQLite、Memory、Diagnostic Log、Reflection、Evolution、Skill 发布及客户端通信和权限 |
| apps/web | React Web 用户交互 |
| apps/desktop | Electron 集成、打包、操作系统原生能力，包含 macOS XPC 及后续 Windows AppContainer Helper 集成 |
| packages/ | 确有复用需求后提取的共享代码 |
| docs/ | 已确定的设计、技术决策、质量要求和交付规划 |
| experiments/ | 技术验证依据及可参考的实验实现 |
| AGENTS.md | 简短、稳定的开发工作规则 |
| package.json | Workspace 入口 |

这是正式开发的逻辑组织建议。具体目录由 Codex 检查仓库后确定，不为了匹配示例而移动已有有效文件。

Desktop 与 Web 是客户端，共享独立 Host；Host 内的各项业务是职责明确的模块，不分别建立一套 Agent 实现。

## 实验成果复用

| 成果类型 | 正式开发处理 |
|---|---|
| Pi SDK、Session、Tool Calling 等原生能力 | 直接使用已有验证依据的 SDK 接口 |
| Session 加密、调度、Skill 发布等宿主逻辑 | 参考实验，整理为正式产品代码 |
| macOS XPC、沙箱和模型通道 | 保留已验证路径，按正式签名与安全要求集成 |
| Faux Provider、模拟凭证和测试夹具 | 继续用于自动化测试，不进入生产业务逻辑 |

不整体复制实验目录，不因原型简单而重新设计；仅在存在明确缺陷、不能满足正式要求或有经核实的更合适 Pi 原生机制时调整。原型通过不免除产品集成与生产环境验证。

## 开发说明与按需读取

AGENTS.md 只保留稳定原则：产品定位、优先复用 Pi、开发前读取相关设计和实验、自主实施和必要测试、重大冲突的裁决边界、保持代码清晰。

设计细节留在 docs/，不复制全部内容到工作说明，也不要求每轮加载全部文档。

| 当前工作 | 按需读取示例 |
|---|---|
| Session | Session 相关设计、TD-05、TD-11、EQ-03 及对应实验 |
| Memory | TD-07、DM-04 及相关验收要求 |

AGENTS.md 约束开发中的 Codex；产品 Skill 管理最终运行的 Agent 能力，不能混为同一套规则。

## 当前决策入口

正式开发维护简短的当前决策索引，记录有效决定、对应文档、已被替代的旧决定和尚未通过的验证。原文继续保留，不再复制一份巨型架构说明。

需识别的取舍包括：

- TD-09 已撤回可信特殊 Skill 必须经过统一 Bridge 的假设。
- 执行隔离采用随应用交付的原生路径，不继续采用已被替代的 Docker 前提。
- TD-07 选择产品 SQLite Memory，不原样安装第三方 Memory 扩展。

当前决定以有效技术验证和正式裁决为准，原型证据仍受版本、环境及覆盖范围约束。该索引、项目目录与 AGENTS.md 属于后续正式开发的组织要求。

## 阶段任务管理

以简洁阶段任务清单管理开发，每个任务保留四项：

| 项目 | 要求 |
|---|---|
| 目标 | 要实现的用户能力 |
| 依据 | 相关设计与实验 |
| 完成标准 | 证明功能实际可用的条件 |
| 实际结果 | 实现内容、验证证据及未解决问题 |

任务内部文件修改、实现顺序与测试安排交给 Codex 自主规划。不建立复杂项目管理系统，不将文件清单或函数完成数量当作交付成果。

例如 Session 安全持久化任务以 TD-05、EQ-03 和实验为依据，交付可保存、恢复和继续使用的会话，验证分支、Compaction、Tool Calling 与敏感信息保护，而非预先规定全部函数拆分。

## 交接与裁决

云端确定阶段目标、约束与验收，本地读取相关资料、自主实现并形成可运行版本和证据，再按阶段标准判断结果。

普通 Bug、代码结构调整及明确的成熟技术选择由本地处理，不要求每次代码修改回到云端。重大需求冲突、核心架构变化、安全要求无法满足或真正需要用户取舍时再讨论。

D1 的任务说明见 [DP-03](./DP-03-D1首个可用产品的开发计划.md)，后续依赖和交付条件见 [DP-04](./DP-04-D2至D5交付依赖与整体验收规划.md)。交付规划约束工程目标，不规定运行中 Agent 的思考步骤。
