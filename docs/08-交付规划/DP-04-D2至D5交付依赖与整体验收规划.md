## D2：能力与知识系统

### 交付要求

普通 Skill 保持 Pi 原生兼容；特殊 Skill 使用 Pi Package 和 Extension。统一管理、编辑、启停、版本记录和回退。

基础 Pi Tool 不提供普通 Skill 的用户禁用开关；调用和资源访问仍由当前活动权限决定，不能据此让 Reflection 获得正常任务的全部权限。原生安装兼容性也不等同于普通 Extension 自带完整安全保证。

产品 SQLite Memory 支持 Global / Project 作用域、来源、知识修正与历史。普通 Agent 可以自主保存和修正知识。描述性 Knowledge 独立修订留史，无需每次发布 Skill Version；当前修订不覆盖历史含义，也不改变正式 Tool、Hooks 或长期行为规则的授权要求。

Diagnostic Log 只保存高价值诊断指标和原始证据引用。Agent 可自主查询并回溯 Pi Session，不复制完整原始历史。

### 验收场景

用户完成任务时，Agent 按需读取 Skill 和 Memory，保存有长期价值的认识。另一个会话能够检索这些认识；用户纠正后，旧结论保留历史，不再作为现行要求。

回档验收覆盖跨会话：Session A 撤销旧分支中的项目决定后，Session B 不能再把该决定作为当前要求。区分来源证据与当前适用性，不能仅凭查询会话的 getBranch() 判断另一会话的决定是否有效；具体规则见 [TD-07](../06-技术决策/TD-07-Memory实现与检索方案.md#回档与知识适用性)。

验收必须证明知识被实际使用、积累和修正，不以数据库 CRUD 完成代替。

## D3：自主反思

### 交付要求

复用既定机制：Pi agent_settled、30 秒 Debounce、SQLite 后台任务、独立 Pi AgentSession、macOS XPC 沙箱 Worker 和 TD-13 受控模型调用通道。

这些机制沿用第六阶段注明版本、环境和范围的实验依据，不重新设计，也不将原型成功写成真实 Reflection 已验收。

系统负责触发、信息访问和真实执行权限；Agent 自主判断哪些行为值得检查、已有认识是否需修正、是否值得积累知识或开发新能力。

Reflection 只能经受控区域或接口更新允许的描述性知识、提交建议，不能修改正式 Tool、Hooks 或长期规则，不能任意改写混合知识与规则的 SKILL.md。日常反思不运行实验，不预设固定分析步骤。

### 验收场景

复杂任务结束后，系统按既定规则启动 Reflection。Agent 自主查阅历史、Log、Memory 与 Skill，需要时实际保存或修正知识，认为值得改进能力时提交建议；用户可在建议中心查看证据。

不要求每次反思都更新知识或产生建议。验收判断自主分析、知识写入及建议通路是否真实可用，不以建议数量或 Faux Provider 调用成功定义完成。

## D4：自主进化

### 实现与验收边界

复用 Pi 原生 AgentSession、bash/Tool Calling、Skill/Extension；独立 Evolution 会话按已获授权的目标开发，候选与正式版本分开。必要检查包括依赖/加载、测试结果、授权范围、不可变版本与失败回退。不新增强制沙箱门槛，也不将 D3 Reflection 的受限 Worker 当成 D4 的执行方式。未隔离代码具备当前用户权限，产品与验收不得宣称具备 OS 级防恶意代码保证。

### 完整业务验收

Agent 自主提出新能力 → 用户批准目标 → 独立 Evolution 会话自主验证、开发和测试 → 必要检查通过 → 自动发布 → 正常 Agent 发现并使用新 Tool。

用户一次批准后，Agent 在授权范围内自主选择实现，通过必要检查后自动生效，不重复审批。新能力可以由已有认识和新需求主动创造，不要求先有失败记录，不另建自进化工作流引擎。

同时验证：

- 验证失败不影响正式 Skill。
- 发布失败可以保留或恢复旧版。
- 新版生效不破坏已有 Session。
- 用户能够查看历史并回退。

能力回退遵守既有版本边界，不自动撤销独立 Memory 或知识修订历史。

## D5：个人自用可靠性交付

| 方向 | 本轮验收 |
|---|---|
| 原生 Pi | 官方 Extension 规范，Agent 主动调用高价值 Diagnostic 查询与证据定位；复用 RE-04 口径和原生 Session，不存第二份完整历史；真实原生 Pi 安装/执行通过 |
| 数据 | Session 加密快照、SQLite、Skill 版本与授权及诊断的备份、迁移和恢复，覆盖失败注入与手动更新后继续使用 |
| 安全 | 真实模型凭证使用与泄露检查、Web 远程认证、来源及范围控制、IPC；不扩大 D4 既定宿主执行权限承诺 |
| 稳定性 | 长时运行、多 Session、Reflection/Evolution 后台活动、关闭重启和资源释放的可观测测试 |
| macOS | 沿用本机有效 Apple Development 签名、Pi Host 与 XPC；可靠打包、打开和手动更新，提供恢复说明 |
| 使用 | 当前功能可用、状态真实、出错能处理；D6 再统一进行美观与完整交互重设计 |

当前 D5 不要求 Developer ID 付费签名与公证、自动更新器、Windows 实机/AppContainer 或公共发行基础设施。Windows 未经验收不得宣称正常可用；自动 Reflection 不能在缺少有效受限环境时降级为高权限运行。更新不破坏正式能力与用户数据，不以测试数量代替恢复结果。原生 Pi 日志扩展既不是完整自进化核心，也不要求复制产品 Host 的 SQLite。

## D6：最终 UI/UX 改造

D5 可靠性验收通过后，Codex 先调研现有 Web/Desktop 用户流程，设计有明确差异的交互和视觉方向，以独立可运行、可交互 Demo 展示信息架构、模块常驻/按需显隐、导航、反馈、响应式布局与视觉语言；可采用许可证合适的成熟开源组件/素材。Codex 负责方案说明与 Demo，不享有最终设计决定权。**用户对信息架构、模块显隐、布局、样式与交互体验最终拍板；未经其明确确认，不能把 Demo 实装到正式前端或替换既有业务 UI。** 根据用户反馈迭代 Demo，确认后再复用既有 React 和业务能力实施，并用真实用户任务、可理解性、交互一致性、Web/Desktop 截图、可访问性和功能回归验收。不以工程调试信息展示充分、换肤或新增组件数作为 UX 成功标准。

当前实施：用户已确认 D6-A「会话书桌」并授权正式整合。Web/Desktop 共用正式 React 界面，实施、真实任务验证及保留限制见 [D6 正式客户端交付](../D6-CLIENT-DELIVERY.md)。最终视觉与长期使用体验仍由用户判断。

## 跨阶段约束

1. Pi SDK 是唯一 Agent 执行核心，正常任务、Reflection 和 Evolution 复用原生执行，不重建 Agent Loop、Tool Calling 或上下文管理。
2. 业务能力独立维护、协作复用，不重复存储或维护第二份业务状态。
3. 工程层负责权限、调度、状态和发布；Agent 自主分析、判断、验证、开发和创造。交付里程碑不变成固定思考流程。
4. 每阶段完成真实集成，用真实 Agent 和实际产品验证；建表、注册 Tool、Faux Provider 调用或模拟界面只是局部技术证据。
