# 个人备份、恢复与手动升级

## 保存备份

在 macOS 的 **Agent → 备份数据…** 选择一个尚不存在的 `.agentbackup` 文件。先结束正在执行的对话、能力开发和后台反思；存在运行任务时，本次备份会被拒绝，任务继续运行。应用在空闲时停止 Host 接收新任务，保存状态、正常关闭，再创建备份，完成后重新连接。

备份包含加密 Session 的当前及上一检查点、Provider 凭据、SQLite 中的 Memory、授权、SkillVersion、Reflection/Evolution 和诊断记录，以及 Skill 版本文件、候选和独立知识修订。SQLite 采用一致性备份。备份整体使用原数据密钥加密；查看用的脱敏 Session 导出不能用来恢复。

请把备份复制到另一块可靠存储。保留原数据目录内的 `data-key.enc` 和原 macOS 钥匙串访问能力；它们与备份一起构成恢复条件。只保留备份文件不能解决数据密钥丢失。默认桌面数据目录为 `~/Library/Application Support/self-evolving-agent/agent-data`；通过 `AGENT_DESKTOP_DATA_DIR` 指定的目录以实际配置为准。

## 恢复到新目录

选择 **Agent → 从备份恢复到新目录…**，先选择备份，再填写一个尚不存在的目标目录。应用使用当前已解锁的数据密钥认证整个备份，核对文件、SQLite 和 Session 后，才发布恢复目录。损坏、密钥不匹配或版本不支持会报错，原数据保持原样。

如果 SQLite、Session 或凭据文件损坏导致服务启动失败，但系统已成功解锁数据密钥，仍可从同一菜单离线恢复。备份仍须通过完整加密认证，密钥不匹配时会拒绝。系统安全存储或密钥本身无法解锁时，不能绕过密钥保护；应先恢复原密钥和钥匙串访问能力。

恢复成功后先退出 Agent。保留当前数据目录，将其移到另一个位置，再把恢复目录移到原路径，然后重新打开应用。也可以在独立启动环境中用 `AGENT_DESKTOP_DATA_DIR` 指向恢复目录。不要直接把恢复文件叠加覆盖到正在使用的数据目录。

如果备份中有原本损坏的 Session、需要上一检查点的会话，或摘要及依赖完整性不通过的 SkillVersion，完成提示会明确列出。备份保留这些原始文件和记录，但不能把已损坏的数据修成可用，也不会重新授予能力执行信任。

重新打开后，检查历史会话、Memory、正式 Skill 和开发活动；用一个熟悉的小任务确认可以继续执行，再决定何时删除旧副本。恢复后的中断操作不会自动重放；文件写入、Shell 或外部服务可能已经产生效果，应先检查实际结果。

同一 macOS 用户下迁移目录会保留原 `data-key.enc`。迁移到另一台 Mac 时，需要同时迁移可解锁原密钥的系统钥匙串，或使用自己另行安全保存的原始数据密钥走维护 CLI；新设备上的替代密钥不能解开旧备份。Windows 受限 Reflection 仍不可用。

## 手动更新应用

1. 等待所有前台、Reflection 和授权开发任务完成，保存一份新的加密备份。
2. 使用 **退出 Agent** 完整退出；关闭窗口仅隐藏窗口，不能作为更新前退出。
3. 保留旧 `Agent.app`，将新包放到原应用位置。应用包与数据目录分开，不移动或删除数据目录。
4. 打开新应用。macOS 如要求钥匙串授权，核对应用身份后处理系统提示。
5. 打开原有会话并继续一个小任务，检查 Memory、正式 Skill、授权记录与后台活动状态。

本机使用既有 Apple Development 签名。该包没有 Developer ID 公证，不作为公开分发包。需要从源码打包时，使用当前有效身份：

```sh
AGENT_CODESIGN_IDENTITY='Apple Development: your identity' npm run package:desktop
```

打包过程先在独立目录完成构建和签名，成功后再发布输出。原输出存在时保留为 `.previous-时间戳` 目录；构建或签名失败不会先删除旧包。不要在安装包仍运行时替换它。

## 更新或数据损坏后

如果新应用无法打开数据，保留失败目录及升级前备份。可以先重新使用旧应用，但旧应用遇到不认识的新数据格式时也必须停止；不要强改版本号。需要使用升级前备份时，按上面的步骤恢复到一个新目录，先检查升级后是否还有需要保留的新工作，再决定切换。

D5 首次打开旧版数据时，会先在原数据目录旁保存 `原数据目录名.pre-d5-标识.agentbackup` 升级前备份，再登记数据格式；升级失败时保留原目录和该备份。它同样需要原数据密钥。不要把自动生成的本机副本当成异地备份。

单个当前 Session 检查点损坏时，应用会尝试上一有效检查点并提示可能丢失的进度；两份都损坏时该 Session 不可恢复，其他有效会话仍可读取。SQLite 或密钥损坏时，应使用已知可用的备份和原密钥恢复，不新建空目录冒充已有数据恢复成功。

备份只覆盖 Agent 数据目录，不包含项目工作目录中的文件或外部服务状态。项目文件仍需使用自己的 Git 或其他备份方式保存。

## 维护 CLI

从源码维护独立 Web 数据，或已另行安全保存原始数据密钥时，先退出使用该目录的 Host。以下命令使用同一个原始 32 字节 Base64 密钥；不能把桌面 `data-key.enc` 文件内容当作原始密钥。

```sh
read -rs 'AGENT_DATA_KEY?原数据密钥（Base64）：'; echo
export AGENT_DATA_KEY
npm run data -- backup /absolute/data /absolute/new.agentbackup
npm run data -- verify /absolute/new.agentbackup
npm run data -- restore /absolute/new.agentbackup /absolute/new-data
unset AGENT_DATA_KEY
```

备份文件和恢复目录必须尚不存在；维护与 Host 使用同一目录锁。进程异常终止后，下一次使用会等待失效锁超时再取得锁。恢复过程中被强制结束时，保留原数据和备份；未完成的空目标及私有暂存目录不能当成成功结果，重新恢复应选择另一个新目录。

## 从其他设备访问 Web

Host 继续仅监听本机回环地址，不直接暴露明文 HTTP。可以使用自己已有的 SSH 通道，在客户端转发相同端口：

```sh
ssh -N -L 4317:127.0.0.1:4317 user@your-mac
```

客户端打开 `http://127.0.0.1:4317` 并输入连接令牌，浏览器 origin 与转发端口必须匹配；自定义端口时两端对应修改。SSH 登录不能代替产品 Bearer/首帧认证。连接令牌不放入 URL。当前专项验证了实际 HTTP/WebSocket 入口的认证及来源拒绝，没有第二台机器或公网 TLS 的实测结论。
