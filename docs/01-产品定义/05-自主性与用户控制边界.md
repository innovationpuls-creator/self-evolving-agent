# 自主性与用户控制边界

## 自由探索，克制打扰

Agent 可以主动积累不限于当前任务的认识和能力构想，只主动提醒其判断具有较高价值的建议，其余内容供用户按需查看。不预设固定通知频率或价值评分算法。

## 学习与正式变更

| 行为 | 自动反思的权限 |
|---|---|
| 阅读历史、Memory、Skill，形成经验和怀疑 | 允许 |
| 新增、修正、合并已有知识区域的描述性内容 | 允许，保留必要来源与历史 |
| 修改 Skill 的长期操作指导和行为规则 | 需要用户批准 |
| 创建任何新 Skill，包括纯知识型 Skill | 需要用户批准 |
| 创建、修改 Tool 或 Hooks | 需要用户批准 |
| 为验证怀疑编写或运行实验 | 留到用户授权后的开发活动 |

描述性知识不因作者是用户或 Agent 而享有不同权威；两者都可以根据证据被质疑与修正。真正的权限区别是内容是否改变长期行为约束或可执行能力，不是文件扩展名或知识作者。

正常 Agent 仍按用户任务权限执行工作，不能把自动 Reflection 的限制扩大为所有日常任务都不可运行脚本。

## 授权与生效

采纳建议后先进入独立会话讨论。Agent 解释问题、依据、新建或修改的原因；用户同意具体目标后，再自主选择验证与实现方式。

授权限于目标范围。检查通过后自动生效，不重复审批；失败保留上一可用版本，支持回退。权限必须在实际资源与执行边界生效，不能只靠提示词。
