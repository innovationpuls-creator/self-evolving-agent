# 首版范围与使用边界

## 首版必须形成的闭环

正常任务执行 → 认识反思 → 有价值知识积累 → 能力或行为改进建议 → 用户讨论与批准 → 验证、开发和测试 → 能力正式生效 → 后续任务使用与再审查。

这是业务活动的关联，不是要求 LLM 按固定顺序思考。首版需要真实实现新 Tool 的开发与使用，不能停在生成建议或代码；也不要求在所有任务领域都能成功创造能力。

## 交付范围

| 范围 | 首版要求 |
|---|---|
| Agent 基础 | 基于 Pi Agent SDK，复用 Agent Loop、Tool Calling、Session 与上下文管理 |
| 能力管理 | 普通/特殊 Skill、多语言脚本、Hooks、按需使用、启停、编辑、版本回退 |
| 历史与知识 | 轻量诊断、原始证据回溯、跨会话访问、Global/Project Memory |
| 自进化 | 自动反思、建议管理、授权开发、自主管理依赖、验证后生效 |
| 客户端 | Web，以及可安装、更新和打包发布的 Windows/macOS 桌面端 |
| 使用方式 | 单用户、多设备、本地与远程访问；远程访问需认证 |
| 安全 | 强制敏感信息保护、真实权限限制、开发不破坏正式运行环境 |

2026-10-21 范围修订：取消“整套自进化核心必须作为 Pi Package 独立安装”的要求。改为提供一个遵循 Pi 官方 Extension 规范的独立诊断模块，使原生 Pi Agent 能按需查询已定义的高价值会话日志与原始证据引用。优先复用 Pi Session 和现有 Diagnostic Log 的指标定义，不移植完整 Memory、Reflection、Evolution 或专用客户端；扩展不得被描述为安全沙箱。

首版个人自用产品优先保障 macOS 本机长期使用、数据安全、备份迁移、手动升级和 Web 远程连接；不以付费 Developer ID 公证或 Windows 实机验证为当前交付门槛，也不宣称未验证平台已正式可用。功能与可靠性完成后，再独立开展最终 UI/UX 设计与改造。

## 范围边界

- 不建设多用户、团队协作、RBAC 或多租户系统。
- Linux 桌面端暂不列入要求。
- 不开发客户端本机远程执行机制，Tool 统一在 Pi 主机执行。
- 不重新实现已有 Agent Harness、脚本解释器或固定反思工作流。
- TypeScript 为项目主体方向；脚本支持 TypeScript、JavaScript、Python、Shell 等，不锁定固定语言白名单。
- 具体框架、数据库、沙箱与桌面打包技术留到技术决策。

优先不修改 Pi Core；如果后续证据显示与强制脱敏、隔离或可靠执行要求冲突，应重新评估方案。
