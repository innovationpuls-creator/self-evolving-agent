# EQ-07：工程质量总审查与阶段收口

## 最终修订

工程质量阶段完成测试、安全、数据可靠性、可观测性、性能和升级要求的设计收口。最终审查的四项修订已并入对应正文，不另建质量模块。

| 问题 | 最终边界 | 规则位置 |
|---|---|---|
| 完整历史与敏感信息 | 快照加密保护静态数据，解密后的模型、Memory、客户端及导出传播仍受授权检查 | [EQ-02](./EQ-02-安全威胁模型与权限边界验收.md#敏感数据的保存与使用) |
| 跨会话 Memory | 历史来源与当前适用性分开，查询会话的分支不能独立判断另一会话决定是否已撤销 | [EQ-03](./EQ-03-数据可靠性与故障恢复验收.md#memory-的来源与当前适用性) |
| 自主知识写入 | 明确受控区域或能力接口，不能仅凭 LLM 分类就任意改写混合知识与规则的 SKILL.md | [EQ-02](./EQ-02-安全威胁模型与权限边界验收.md#知识更新与能力发布) |
| 原型与产品 | Faux Provider、夹具和基础设施原型不替代真实业务端到端验收 | [EQ-01](./EQ-01-质量目标与验收体系.md#三层测试) |

上述修订不改变既定 Session 架构、Pi 执行机制或 Skill 统一管理方式。

## 五个验收方向

以下状态承接原对话和第六阶段记录的证据范围，表示工程验收起点；质量设计完成不等于产品已经实现或发行验收通过。

| 方向 | 核心要求 | 已有依据与待完成项 |
|---|---|---|
| 功能正确性 | 正常 Agent、Memory、Reflection、Evolution 完成完整业务场景 | 真实产品业务流程待实现及端到端验收 |
| 数据可靠性 | Session、SQLite、Skill 安全保存、恢复与升级 | 关键原型有证据，产品集成、故障恢复及升级验收待完成 |
| 权限安全 | 实际阻止未授权执行和敏感数据传播 | 产品数据通道与 D4 授权发布仍需各自业务验证，不额外要求生成代码沙箱 |
| 运行稳定性 | 多会话、后台、长期运行及重连保持可靠 | 部分原型有证据，压力与长期运行测试待完成 |
| 交付兼容性 | Windows/macOS 实际安装、升级、运行与恢复 | macOS 部分原型通过，正式签名、公证与发行待验收；Windows 仍待实测 |

TD 文档分别注明版本、环境和夹具范围，不将独立机制通过等同于整体安全。完整自我反思、知识积累、建议和授权进化仍需在真实产品中证明，不能只确认工具可调用。

## 保留的工程原则

1. 使用模块、Pi 集成、产品端到端三层测试，按变更影响选择检查。
2. 权限与数据保护由实际边界保证，不能仅依赖 Prompt 或普通 Extension。
3. 恢复遵循各自权威来源，不盲目重放未知外部副作用。
4. Pi Session 保存原始证据，Diagnostic Log 服务 Agent，System Log 服务工程排障，前端独立提供轻量反馈。
5. 性能优化先测量，不为假想瓶颈增加基础设施或限制正常推理。
6. 应用、Pi SDK、SQLite Schema 与 Skill 分别管理版本，知识修订继续独立留史。
7. 正式发行在目标操作系统验证实际安装包、升级、恢复与安全边界。

## 收口范围

正常任务、Reflection 和 Evolution 继续复用 Pi SDK；保持单 Host、SQLite 与 Node 调度，不新增 Agent 框架、独立队列或重复历史系统。不建立以固定分数定义认识与创造能力的复杂评估平台。

Windows Reflection 的实际执行能力需在目标系统验证；D4 不额外要求 AppContainer 或其他代码执行沙箱。

第七阶段的输出是工程质量约束和验收依据。第八阶段的[交付规划](../08-交付规划/DP-01-产品开发顺序与阶段性交付.md)承接这些要求，明确开发顺序与阶段验收，不将待验收事项改写为已完成事实。
