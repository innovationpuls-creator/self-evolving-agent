# EQ-01：质量目标与验收体系

## 质量目标

工程质量阶段确定怎样证明产品可靠、安全且能够长期使用。既有技术实验转化为产品回归测试，不重新选择已经确定的架构。

| 目标 | 验收要求 |
|---|---|
| 运行可靠性 | Agent、Session 和后台任务不因窗口关闭、会话切换或普通组件故障而丢失 |
| 数据完整性 | 会话、Memory、Skill 版本和进化记录能正确保存、恢复及追溯 |
| 安全性 | 敏感信息不发生未授权传播，Reflection 和生成代码不能绕过实际权限 |
| 兼容性 | 保留 Pi 原生能力，Web、Windows、macOS 的核心行为符合既定要求 |
| 可维护性 | Skill 可独立更新、测试、禁用及回退，组件故障不引发无关功能失效 |

这些是既有需求的质量约束，不增加产品功能。

## 三层测试

| 层次 | 覆盖内容 | 方法与证据边界 |
|---|---|---|
| 模块测试 | Memory、调度、权限判定、版本管理和数据转换 | 优先使用确定性单元测试 |
| Pi 集成测试 | 原生 Agent Loop、Tool Calling、Session 恢复、Extension 加载及 Reflection IPC | 复用 Faux Provider 和既有实验中的有效用例 |
| 产品端到端测试 | 安装后的 Web/Desktop、真实模型、后台运行、安全隔离和异常恢复 | 在实际操作系统及打包应用中执行 |

TD-01～TD-13 是集成测试的依据，不要求原封不动搬入全部实验脚本。Faux Provider、固定夹具和独立工具调用不证明完整的自主反思、知识积累、进化建议与授权开发已经可用；正式产品还需覆盖这些真实业务场景。

## 关键回归场景

| 能力 | 必须保持的行为 |
|---|---|
| Pi Session | 加密保存、历史分支、Compaction、恢复后继续执行 |
| Memory | 修正保留历史，回档后废弃决定不成为当前要求，跨会话共享同样遵守适用性 |
| Reflection | 30 秒调度、独立执行、不递归触发、不越权，分析方向与是否产出由 Agent 决定 |
| Skill | 更新不中断在途任务，禁用真正生效，失败回退；基础 Tool 仍按活动权限执行 |
| Evolution | 未授权不修改正式能力，授权范围内开发、验证及发布 |
| 模型通道 | Worker 不持有密钥，Host 检查模型授权，错误与取消正确传递 |
| 故障恢复 | 识别中断，不盲目重放结果未知的外部副作用 |

实际发现过的故障应固定为回归用例，包括 TD-11 的 Reload 后 Tool 激活状态变化。测试验证功能、权限、数据和可观察结果，不以固定规则或分数定义 Agent 的认识与创造能力。

## 按变更影响选择验证

| 变更 | 最低验证要求 |
|---|---|
| 描述性知识更新 | 格式、引用及知识写入权限检查，不逐次发布 Skill Version 或重验全部执行代码 |
| Tool / Hook 代码更新 | 相关能力、权限、版本切换及回退测试 |
| Session / SQLite 变更 | 一致性、迁移及恢复测试 |
| IPC / 安全策略变更 | 正向功能与越权拒绝测试 |
| Pi SDK 升级 | 核心集成回归测试 |
| 正式发行 | 全部关键测试及对应操作系统的实际安装包验收 |

不因普通 Markdown 修改运行完整跨平台测试，不追求脱离实际价值的覆盖率数字，也不建设独立的大型测试平台。

## 失败与发布边界

- 核心运行失败时保留可恢复会话和已提交业务状态，不伪造成功。
- Reflection、诊断和建议等非核心功能失败时限制影响，不中断正常 Agent。
- 安全验证失败时拒绝危险操作。受限环境不可用时报告对应功能不可用，不静默退回高权限 Pi。

正式发行验证实际安装产物。macOS 开发实验不能替代正式签名、公证后的安装验收；Windows 交叉打包不能替代 Windows 启动、Tool Calling、Session 和 AppContainer 实测。

故障测试覆盖检查点损坏、进程意外退出、升级失败和未知副作用恢复，使用模拟数据与隔离环境。正常退出成功不是充分的恢复证据。
