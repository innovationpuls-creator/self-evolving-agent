# EQ-04：可观测性与故障定位

## 三类记录

可观测性同时服务 Agent 自主认识、工程排障与用户状态反馈，沿用既有历史和诊断职责，不新增日志框架。

| 记录 | 职责 | 来源与保存 |
|---|---|---|
| Pi Session | 对话、执行历史及原始证据 | Pi 原生结构，Host 加密快照 |
| Agent Diagnostic Log | 分析工具使用、效率、异常及能力局限 | Pi 运行事件，SQLite 轻量指标与索引 |
| Host System Log | 排查进程、数据库、IPC、沙箱和客户端故障 | 独立管理的宿主结构化日志 |

三类记录共用必要关联标识，不互相替代。一次 Tool 调用的完整参数和结果保留在原始历史中，不在诊断与系统日志中重复复制。

## Diagnostic Log

| 类型 | 必要信息 |
|---|---|
| 执行 | Session、Trace、开始与完成时间、最终状态 |
| 模型 | 名称、Token Usage、缓存、费用与错误 |
| Tool | 名称、调用关系、耗时、成功或失败，以及既有需求要求的输出规模特征和原始结果引用 |
| 上下文 | Compaction、上下文变化与原始条目引用 |
| 能力 | Skill 使用、版本与 Memory 访问 |
| 异常 | 重试、中断、超时及失败位置 |

SQLite 保存便于跨会话查询的索引、指标及原生历史未完整覆盖的运行事实，可由 Session 重建的内容不保存完整副本。

原对话将 `session.subscribe()` 事件和嵌套调用的 `parentToolCallId`、有限诊断结果作为优先复用途径。具体覆盖以对应 SDK 的集成测试为准；确需补全跨会话调用关系时，只补必要的轻量事件。截断或不完整记录必须可识别，不能当作完整事实。

正常 Agent、Reflection 和用户主动重新审查共用诊断访问能力。LLM 自主查询、回溯证据和分析原因；不以重复次数、耗时或输出大小预先判定浪费，也不将指标直接转换为进化建议。

## Host System Log

系统日志记录确定性的工程故障，包括 Host 启动、SQLite 事务与迁移、快照恢复、Worker 启动及 IPC、Skill 切换、客户端连接与同步异常。工程故障不依赖 Reflection 才能发现。

复用成熟 Node.js 结构化日志方案，具备等级、关联 ID 和轮转即可，不部署独立日志服务器。系统日志不默认全部提供给 Agent，需要排障时通过受控接口读取相关脱敏内容。

日志不默认保存完整 Prompt、Tool 参数、HTTP 请求头或含凭证的异常对象。检查第三方依赖错误、Worker 标准输出及开发测试日志，在写入和外发前保护敏感信息；无法安全保存的字段不记录。必要安全检查失败不得放行未经检查的数据。

完整加密 Session 与脱敏日志的保护方式不同，解密后传播仍受授权约束，见 EQ-02。

## 前端状态

| 通道 | 内容 |
|---|---|
| 实时运行反馈 | Pi 订阅与 Host 推送的当前操作、Tool 执行及 Reflection 状态 |
| 持久重要状态 | SQLite 中的任务、建议、发布及异常结果，供重连后查看 |

不把每个流式事件写入数据库，也不要求用户打开日志才能了解执行状态。

Tool 执行展示当前操作及必要反馈；Reflection 默认轻量、可展开；Skill 更新展示版本及结果，失败说明是否已回退；沙箱不可用明确反馈对应功能不可用，普通聊天不受无关故障影响；重连恢复当前状态和重要事件。

详细诊断按需展开，不增加常驻监控仪表盘，不将内部日志直接用作用户界面。

## 验收要求

- 异常可定位至对应 Session、Trace、Tool 与 Skill 版本。
- Diagnostic Log 不重复保存完整对话或 Tool 输出。
- Session、日志、诊断查询和前端反馈各有明确的数据访问边界。
- 诊断采集故障不停止普通 Pi Agent Loop，缺失记录可识别；这不允许绕过必要安全检查。
- 重连展示真实任务状态，失败不显示为成功。

覆盖跨会话查询、异常关联、输出规模回溯、敏感信息泄露和客户端重连，沿用 RE-04 的既有诊断验收要求。
