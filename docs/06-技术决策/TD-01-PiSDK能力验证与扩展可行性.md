# TD-01：Pi SDK 能力验证与扩展可行性

## 最终决定

继续复用 Pi 的 Agent Loop、Tool Calling、Session、分支、Compaction、Tool 发现和生命周期事件。用户明确选择：**兼容 Pi，严格安全由受控运行环境保证。**

Pi Package 保留原生分发与独立安装能力；普通 CLI 中安装 Extension，不等于取得完整产品的敏感信息保护和执行隔离。

## 四项验证与架构影响

| 议题 | 原对话实验结论 | 宿主需要补充 |
|---|---|---|
| P0-01：Session 敏感信息保护 | 部分满足；消息过滤不能覆盖所有写入，还可能改变 Tool 参数 | 安全持久化、恢复及导出 |
| P0-02：执行权限与隔离 | Extension 单独无法满足；初始化代码可直接访问系统资源 | 真正的进程与操作系统权限边界 |
| P1-01：Tool / Hooks 生命周期 | 注册、发现、隐藏、替换和重载可复用，但不等于发布管理 | 版本验证、切换、回退与持久禁用 |
| P1-02：Session 与后台反思 | 历史恢复、独立 Session 和 settled 事件可复用 | 30 秒计时、任务持久化与中断恢复 |

原对话的六项最小实验使用 Pi SDK 1.3.0、Faux Provider 和模拟凭证，基线源码为 [71023aec](https://github.com/earendil-works/pi/tree/71023aec1546d6d677a65669c5665c0927ce0dd0)。实验在临时目录执行并已清理；本地没有独立 TD-01 报告，依据为原对话提交的验证正文及后续验收。

## 关键取舍

在 `message_end` 修改执行中的消息，会让 Tool 收到掩码而非真实凭证；`appendCustomEntry` 等路径还可能绕过过滤。因此不继续叠加消息过滤器作为主要持久化方案，执行对象和保存副本必须分离，后续由 TD-05 确定完整加密快照。

Extension、文件工具及子进程的实际权限，不能靠工作目录、Prompt 或 Tool Hook 撤销。嵌套调用可经过 Hook，不代表直接文件访问也受控制。

`agent_settled` 表示 Pi 没有待自动继续的工作，不是任务成功证明，也不是 30 秒计时器。Hook 派发会等待处理器返回，因此处理器只登记工作并及时返回，后台活动另行调度。

## 可行性与剩余边界

本项收口的是原生可复用部分及缺失边界，不是宣告两个 P0 风险当时已经解决。持久化路线见 TD-05，后台调度见 TD-08，能力生命周期见 TD-09～TD-11，隔离及模型通道见 TD-12、TD-13。

后续路线不需重写 Pi Core，但证据仍受版本、平台和原型范围限制，不能从受控 SDK 原型推断普通 CLI 已具有同等安全保证。
