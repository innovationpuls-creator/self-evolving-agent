# RE-04：Agent 运行诊断与历史信息访问

## 数据分工

优先使用 Pi Session 保存原始执行历史。Diagnostic Log 只补充面向 Agent 自我分析的结构化指标、调用关系和原始证据引用，不建设第二份完整对话日志。

原始历史长期保留，不因总结、压缩或关闭会话而自动删除；只在实际运行产生事件时追加记录。停止运行不等于历史失效，反思活动的可观察执行也应可追溯。

## 高价值诊断范围

| 类别 | 需要的信息 |
|---|---|
| 任务表现 | Turn 数、耗时、实际结束状态、可观察的用户纠正 |
| 模型成本 | Input/Output Tokens、Cache Read/Write、模型及可获得费用 |
| Tool 使用 | 名称、次数、时长、错误状态、输出规模、参数特征与重复调用特征 |
| 执行异常 | 失败、重试、中断、错误类型与恢复情况 |
| 上下文变化 | Compaction 次数、原因及可获得的压缩前规模 |
| 能力使用 | 可观察的 Skill 加载、知识访问、Tool 使用、变更及相关版本 |

这些是目标信息范围，不表示 Pi 当前已完整提供。原对话列出的候选来源包括模型 usage、Tool 生命周期及 Session 记录；实际字段、版本和覆盖程度仍待验证。

## 事件关系与证据

诊断信息应关联会话、有效分支、Trace、Turn 及 Tool 调用。调用顺序、必要参数特征、嵌套关系与原始来源需足以支持进一步检查。

重复调用只能记录为可观察特征，不能直接判断为浪费；文件变化或再次验证都可能合理。模型 stop reason 或 Agent 停止执行，也不能直接证明用户任务成功。

输出规模同样只记录可观察特征及原始结果引用，是否异常由 Agent 判断，不为此复制完整输出。

嵌套 Tool 调用、Skill 加载、能力版本与知识使用是否有足够原生记录，需要检查；确有缺口且影响分析时才补充采集。

## 查询与排除项

支持跨会话概要查询、筛选、比较与原始证据定位，由 Agent 自主选择读取顺序。不重复存入诊断 Log 的内容包括：

- 完整对话、大段 Tool 输出、图片与完整 JSON。
- 每次模型请求上下文、System Prompt 与 Tool Schema 全文。
- 每个流式片段、逐 Token 事件、模型 Thinking 原文。
- 未经证实的行为好坏判断，以及应进入 Memory/Skill 的知识结论。

原始内容仍可在受保护来源按需回溯。Session 与新增数据都必须在持久化、模型外发及客户端展示前遵守敏感信息保护。

## 验收标准

使用包含多 Turn、重复调用、失败恢复、上下文压缩及嵌套调用的任务，验证诊断信息能以较少上下文定位值得检查的特征，且可回到正确的原始证据。

对于大段 Tool 输出，应能通过规模特征和引用定位结果，再按需读取原始证据，不将完整输出重复写入诊断 Log。

同时检查跨会话与分支关联、历史保留、指标真实性及脱敏范围；不可用信息如实标明，不以推测补全。
