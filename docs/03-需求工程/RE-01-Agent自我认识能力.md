# RE-01：Agent 自我认识能力

## 需求目标

系统应提供持久、可检索、可追溯的自身运行信息，使 Agent 能跨会话审查自己的行为、知识、工具及认识局限。审查不依赖显式错误触发，也不要求产生改进建议。

自我认识与自我改进分别成立：认识到证据不足、明确当前判断边界，也可以是有效审查结果。

## 信息可获得性

| 信息范围 | 应能按需访问的内容 |
|---|---|
| 任务与上下文 | 用户目标、执行时可见信息、上下文压缩与变化 |
| 可观察行动 | 模型输出、行动选择、Turn、Tool Calling |
| 工具行为 | 参数、结果、异常、使用历史及调用关系 |
| 资源消耗 | Token、缓存、模型调用成本、执行耗时 |
| 知识使用 | 可观察的 Skill、Memory 检索与加载情况 |
| 历史认识 | 结论、经验、怀疑及其依据 |
| 能力变化 | Skill、Tool、行为指导的变更与验证结果 |

“完整”指必要的可观察证据可被访问，不等于重复保存全部数据，也不等于能够观察模型未提供的内部推理。原生记录不足之处需识别，不能凭空补全。

## 自主审查

Agent 自主选择审查对象、证据和分析方式，可以重新评价旧认识、比较历史任务、识别未验证前提或推导新能力。

系统不规定固定步骤、问题数量、输出长度或强制评分。反思触发遵循 RE-05，但触发条件不决定推理路径。

## 验收场景

| 场景 | 可接受表现 |
|---|---|
| 无错误任务 | 能审查依据与边界；有依据才提出怀疑，不编造缺陷 |
| 跨会话行为比较 | 自主找到实际历史，比较重复调用、成本与失败恢复，形成有依据的判断或承认证据不足 |
| 旧认识遇到新证据 | 能找到原认识与新旧证据，支持、修正或推翻旧结论 |
| 形式化反思 | 仅出现“可能有局限”“未来可优化”等套话，不能据此认定满足需求 |

采用多种任务评价证据利用与认识质量；单次表现不构成所有情况下都会自主怀疑的保证。
