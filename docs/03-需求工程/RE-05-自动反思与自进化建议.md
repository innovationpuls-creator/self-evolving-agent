# RE-05：自动反思与自进化建议

## 触发与生命周期

| 编号 | 规则 |
|---|---|
| REF-01 | 一次用户任务稳定结束后，等待 30 秒再触发反思 |
| REF-02 | 等待期间继续对话，合并同一有效分支的待分析内容，待新任务结束后重新计时 |
| REF-03 | 用户主动结束或切换会话，可提前将待反思内容标为可执行 |
| REF-04 | 多会话独立运行和反思，互不阻塞 |
| REF-05 | 反思不影响正常 Tool Calling 和聊天体验 |
| REF-06 | 待处理活动不能因关闭客户端、进程重启而永久丢失 |
| REF-07 | 重复事件不能导致同一段执行记录被重复反思 |
| REF-08 | 反思结束不自动触发对自身的新一轮反思 |

关闭窗口与主动结束会话不同；主机仍运行时继续处理后台工作。恢复要依据实际记录，不盲目重放状态不明的操作。

原对话选择 agent_settled 作为候选稳定结束信号，其具体语义与 SDK/CLI 可用性仍需验证，不将 Turn 结束直接等同于完整任务结束。

## 分析自主与信息访问

Reflection 独立运行，可按需访问本次及历史 Trace、轻量诊断、原始 Session、Global/Project Memory、Skill 和过去反思、进化结果。

触发来自当前 Trace，不限制分析只能覆盖当前 Trace。系统不预拼全部上下文，也不规定检查顺序、怀疑数量或强制成果。

## 允许的结果与权限

| 结果 | 约束 |
|---|---|
| 反思记录 | 保存审查对象、判断依据、发现与不确定性 |
| Memory 更新 | 保存、修正有长期价值的描述性知识 |
| Skill Knowledge 更新 | 修改已有 Skill 的认识、经验与局限 |
| 进化建议 | 提出创建能力、修改 Tool 或行为指导的构想 |

每次留下必要记录，但其余结果均可不发生，彼此没有强制依赖。日常反思可只读查询、分析、更新允许区域的知识；不能自行做验证实验、创建 Skill 或修改正式 Tool、Hooks、长期行为规则。

## 建议信息

建议说明改进目标、形成原因、相关依据、预期价值、不确定性和建议操作。新构想不必源于错误，只主动提醒有较高价值的建议，其余按需查看。

反思也可研究过去的反思行为，无需另建“反思的反思 Agent”；修改反思机制自身仍需授权。

## 验收场景

检查 30 秒触发、连续对话合并、会话切换提前触发、关闭客户端与重启恢复、去重及不自循环。

通过无错误任务、没有新成果、跨会话形成认识等场景评价分析质量；验证未经批准不能执行实验或修改受保护能力。形式合规不等于认识质量达标。
