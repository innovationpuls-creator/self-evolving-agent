# RE-07：Skill 扩展与 Pi 原生兼容

## 兼容目标

原生 Pi 的独立交付范围已调整为“高价值会话日志查询扩展”，不再要求整套自进化核心独立安装。复用 Pi 原生 Session、Extension 事件与 `pi.registerTool()`，按需为 Agent 提供日志搜索、详情与原始证据定位；日志口径沿用 RE-04 和现有 Diagnostic Log，原生信息不足时如实标记，必要时仅补充少量结构化指标，不另存完整对话。Pi Extension 不构成安全沙箱；D4 产品内自主进化继续由现有 Host/Skill 系统承担。

## 功能需求

| 编号 | 需求 |
|---|---|
| EXT-01 | 优先通过 SDK/Extensions 实现，原则上不修改 Pi Core |
| EXT-02 | 普通 Skill 原生兼容，特殊 Skill 扩展 Tool、Hooks |
| EXT-03 | 不重新实现 Tool Calling、Agent Loop、上下文管理 |
| EXT-04 | Agent 自主发现并按需使用已启用 Skill 的能力 |
| EXT-05 | Hooks 使用 Pi 支持的事件和语义，不固定数量 |
| EXT-06 | 统一 Skill 管理；禁用时附属可选能力停止生效 |
| EXT-07 | 原生 Pi 日志模块使用官方 Extension 机制，可按官方推荐路径加载或以最小 Package 分发；无需将整个自进化 Host 打包 |
| EXT-08 | 扩展能力配套准确 Markdown 文档与可运行示例 |
| EXT-09 | 原生环境与 SDK 客户端集成保持一致的核心能力 |
| EXT-10 | 加载、更新、卸载不破坏 Pi 基础能力和正在运行的任务 |

EXT-01 是优先复用原则。需要改动 Pi Core 前先评估 SDK 扩展点；不要为未经用户要求的执行隔离新增基础设施。对凭证泄露、版本一致性和功能可靠性仍按各自明确验收要求处理。

## 原对话指出的兼容风险

- 携带脚本的普通 Skill 不应被假定会自动注册为 Tool；可执行连接由 Extension 承担。
- SDK Session 与 CLI 的默认扩展加载可能不同，特别是 codemode、tool_search、MCP，不能默认能力已经一致。
- Tool 从模型列表消失不代表不可间接调用；动态禁用与注销接口的实际能力需验证。
- Hooks 有观察与干预语义之别，不假定每种事件都允许修改 Agent 行为。
- Extension 不构成天然执行隔离。

以上是原对话形成的技术判断与风险，尚不替代具体版本、源码与实验结论。

## 独立诊断模块与验收

原生 Pi 日志模块优先采用官方 Extension，注册模型可调用的查询 Tool；若选择 Package，仅将模块作为最小资源单元，不带入 Host 或整套自进化工作流。日志查询遵守当前项目或明确授权的会话范围，敏感数据不自动注入模型上下文；缺失的历史、指标或原始证据明确标记为不可用。

在实际原生 Pi 环境中验证加载、Agent 主动 Tool Calling、多个真实 Session 的日志检索、分支与原始 Entry 定位、缺失信息处理及卸载。正常客户端继续验证现有 Tool/Skill 的发现、禁用与回退，不把 SDK 模拟测试当成原生 Pi 已通过。源码说明包含安装、使用与边界；不额外开发 Memory/Reflection/Evolution 的原生副本。
