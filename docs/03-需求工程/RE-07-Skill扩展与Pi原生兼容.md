# RE-07：Skill 扩展与 Pi 原生兼容

## 兼容目标

自进化核心尽可能作为 Pi 原生可安装扩展运行，不重新开发 Agent Harness。普通 Skill、特殊 Skill、Tool 与 Extension 保持各自运行职责，统一的是能力管理入口。Pi Package 原生兼容并不自动保证安全；执行代码按当前用户权限运行。D4 不额外要求沙箱；凭证保护和业务权限检查仍由各自的存储与服务实现。

## 功能需求

| 编号 | 需求 |
|---|---|
| EXT-01 | 优先通过 SDK/Extensions 实现，原则上不修改 Pi Core |
| EXT-02 | 普通 Skill 原生兼容，特殊 Skill 扩展 Tool、Hooks |
| EXT-03 | 不重新实现 Tool Calling、Agent Loop、上下文管理 |
| EXT-04 | Agent 自主发现并按需使用已启用 Skill 的能力 |
| EXT-05 | Hooks 使用 Pi 支持的事件和语义，不固定数量 |
| EXT-06 | 统一 Skill 管理；禁用时附属可选能力停止生效 |
| EXT-07 | 优先复用 Pi Package 的安装、更新与卸载 |
| EXT-08 | 扩展能力配套准确 Markdown 文档与可运行示例 |
| EXT-09 | 原生环境与 SDK 客户端集成保持一致的核心能力 |
| EXT-10 | 加载、更新、卸载不破坏 Pi 基础能力和正在运行的任务 |

EXT-01 是优先复用原则。需要改动 Pi Core 前先评估 SDK 扩展点；不要为未经用户要求的执行隔离新增基础设施。对凭证泄露、版本一致性和功能可靠性仍按各自明确验收要求处理。

## 原对话指出的兼容风险

- 携带脚本的普通 Skill 不应被假定会自动注册为 Tool；可执行连接由 Extension 承担。
- SDK Session 与 CLI 的默认扩展加载可能不同，特别是 codemode、tool_search、MCP，不能默认能力已经一致。
- Tool 从模型列表消失不代表不可间接调用；动态禁用与注销接口的实际能力需验证。
- Hooks 有观察与干预语义之别，不假定每种事件都允许修改 Agent 行为。
- Extension 不构成天然执行隔离。

以上是原对话形成的技术判断与风险，尚不替代具体版本、源码与实验结论。

## 自进化自身与验收

自进化 Skill 也可以被分析、提出改进；行为规则与代码变更仍须授权。

分别验证原生 Pi 安装、普通 Skill 兼容、特殊 Tool 实际执行、按需发现、禁用后直接/间接不可调用、Hooks 不破坏原生行为，以及 SDK 集成与客户端能力一致性。

还应让 Coding Agent 按配套 Markdown 独立创建并使用新的特殊 Skill，以验证文档可用性。
