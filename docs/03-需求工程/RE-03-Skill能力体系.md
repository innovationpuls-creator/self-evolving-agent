# RE-03：Skill 能力体系

## 功能规则

| 编号 | 需求 |
|---|---|
| SK-01 | 兼容标准 SKILL.md，保持普通 Pi Skill 的使用方式 |
| SK-02 | 特殊 Skill 可携带接入 Pi Tool 的执行模块 |
| SK-03 | 支持 TypeScript、JavaScript、Python、Shell 等脚本，复用运行环境 |
| SK-04 | Agent 根据任务自主发现、读取和加载已启用 Skill |
| SK-05 | 知识、代码与历史资料按需加载，不全部注入上下文 |
| SK-06 | 实际调用沿用 Pi 原生 Tool Calling |
| SK-07 | 支持 Pi 原生生命周期 Hooks，不固定为某个数量 |
| SK-08 | 保存对能力的理解、实践经验、局限和怀疑 |
| SK-09 | 前端支持查看、编辑、启停、版本管理与回退 |
| SK-10 | 描述性知识、行为规则和可执行代码可分别修改与验证 |

## 能力与内容边界

一个 Skill 可以提供多个相关 Tool。Pi 必要基础 Tool 保留原生实现，不提供普通 Skill 的用户禁用开关，不为统一展示而重新实现。其调用与资源访问仍受当前活动的执行权限约束，自动 Reflection 不因基础 Tool 被保留而获得正常任务的全部操作权限。

描述性知识更新不应意外修改代码或长期行为规则，也不要求重新加载整个执行环境。创建任何新 Skill、修改 Tool、Hooks 或长期行为指导需要用户批准；用户直接编辑和授权后 AI 编辑操作同一份内容。

禁用 Skill 后，其附属可选执行能力必须不可调用，覆盖直接和间接路径。版本检查失败时保留上一可用能力。

## 配套文档

扩展能力必须有准确的 Markdown 说明，覆盖职责、用途、输入与输出、调用方式、依赖、限制、示例以及相关 Pi 接口。内容支持按需读取，便于 Agent 理解、使用和维护。

具体声明格式、解析协议和文件布局留到技术决策，不在需求阶段增加约束。

## 验收标准

- 普通 Skill 能安装、发现、读取和使用。
- 特殊 Skill 提供真实可执行 Tool，使用原生 Tool Calling。
- 新会话、上下文压缩后仍能重新发现已保存能力。
- 知识可以自动积累，正式规则和代码不能未经授权改变。
- 前端管理有效，更新失败、禁用或回退不破坏无关 Skill。
- Skill 与知识数量增长后仍按需读取，不将全部内容常驻上下文。
