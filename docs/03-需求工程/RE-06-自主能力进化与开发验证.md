# RE-06：自主能力进化与开发验证

2026-10-21 [D4 独立 VM 补验收](../D4-VM-EXECUTION-REVIEW.md)仍不准入；EVO-07 的一次目标授权及验证后自动生效目标不变，局部实验通过不授予高权限 Host 执行资格。

新增隔离版本的受限使用契约已批准；当前正式 fixture 实测 Host read/bash 可读取并执行原始源码、同 UID 可读写 live VM backing，故正式执行同边界要求失败。不能以局部 VM 测试通过授予发布资格，既有正式版本保持原语义。

## 功能需求

| 编号 | 需求 |
|---|---|
| EVO-01 | 自主提出改进或全新能力建议，不以执行失败为前提 |
| EVO-02 | 建议独立持久化，可跨会话查看、忽略、归档与采纳 |
| EVO-03 | 新建 Skill、修改正式执行能力或长期规则须获用户批准 |
| EVO-04 | 采纳后进入独立讨论会话，按需读取相关历史 |
| EVO-05 | 自主选择验证问题、用途或可实现性的方法 |
| EVO-06 | 授权内自主编写脚本、修改内容、管理依赖和运行测试 |
| EVO-07 | 检查通过后自动生效，不重复批准 |
| EVO-08 | 失败保留旧版，正式版本可回退 |
| EVO-09 | 开发不阻塞普通任务，未验证修改不影响正式能力 |
| EVO-10 | 改进原因、内容、测试与认识依据可追溯 |

## 授权与自主开发

用户采纳建议后先讨论具体目标。获得目标范围授权后，Agent 自主选择实现方式，继续使用 Pi Agent 与 Tool Calling，不另建 Coding Agent。

开发可以使用 TypeScript、JavaScript、Python、Shell 等，按需安装依赖并记录必要运行要求；开发环境不能破坏 Pi 正式运行环境或影响无关资源。

全新能力可以验证用途、可实现性和预期收益，不必先证明现有能力有错误。

## 各类成果分别成立

| 验证结果 | 处理 |
|---|---|
| 原认识有误或怀疑不成立 | 修正描述性知识，保留依据 |
| 方法需要调整 | 授权范围内修改长期行为指导 |
| Tool 需改进 | 授权范围内修改执行代码 |
| 存在新能力需求 | 授权范围内创建新 Skill |
| 价值不成立、失败或用户取消 | 可以结束活动，不强制产出代码或新版本 |

知识、代码、建议状态与日志不组成必须一同成功的固定工作流。

## 生效与回退

新版本必要检查通过前，旧版继续可用，已经开始的 Tool 执行保持版本一致。正式版本统一由 Skill 管理，不为 Tool 另设重复版本体系。

Skill 回退不自动回退 Memory，不改写 Log；依赖特定版本的知识要能回溯适用背景。

## 验收场景

1. 已有 Tool 改进：讨论授权、验证修改、测试、生效，并可恢复旧版。
2. 全新 Tool：创建特殊 Skill，实际运行后，新的普通会话能自主发现和调用。
3. 无代码成果：验证推翻原怀疑，允许结束活动并保存知识。
4. 开发失败：旧版和普通任务正常，失败原因及过程可回溯。
5. 行为进化：只修改获批的操作指导也可构成有效结果，不以代码产出为条件。
