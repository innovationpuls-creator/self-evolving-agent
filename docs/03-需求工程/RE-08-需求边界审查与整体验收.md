# RE-08：需求边界审查与整体验收

## 统一后的需求边界

| 主题 | 最终约束 |
|---|---|
| 历史完整与诊断轻量 | 原生历史承载证据，诊断仅保留高价值信息、关系和引用 |
| 反思触发与自主推理 | 生命周期规则确定，分析方向不固定，日常不自行实验 |
| Skill、Memory 与 Log | 分别管理能力、长期认识与运行事实，可关联但不合并 |
| 学习与正式修改 | 描述性知识可自主修正，行为规则、Tool、Hooks 与新 Skill 受授权控制 |
| 权限实现 | 必须覆盖实际资源和执行路径，不仅依赖提示词 |
| 进化成果 | 能力与行为均可进化，不要求产出代码 |
| 产品反馈 | 状态真实及时、按需展示，重要事件持久可查 |

## 首版核心能力

首版包含 Pi 原生执行、Skill 管理、运行诊断、长期记忆、自我反思、自主进化以及 Web/Windows/macOS 客户端七组能力。

正常聊天、会话管理、模型设置、安装更新等常规能力优先复用成熟实现，不额外创建重复 Agent 系统。2026-10-21 起原生 Pi 交付范围收敛为独立诊断 Extension：允许 Agent 主动检索高价值会话日志和相关证据，不移植完整自进化核心。产品自进化闭环仍在现有 Host 中实现，Extension 安装成功不代表具备完整敏感信息或系统隔离保证。

## 整体验收

### T-01：基础兼容

在原生 Pi 环境加载独立 Diagnostic Extension，Agent 实际通过原生 Tool Calling 检索高价值会话指标并定位原始证据；使用已发生的 Pi Session 测试跨会话及分支关联，原生信息缺失需明确说明。现有 Web/Desktop 产品继续保持 Skill、Memory、Reflection、Evolution 完整能力，不要求原生 Pi 承载整套自进化功能。基础兼容通过不替代 T-06 的安全验收。

### T-02：历史行为分析

执行多个包含重复操作、上下文消耗和失败恢复的任务，再在新会话分析历史。Agent 能自主检索诊断、访问原始证据，并以较少上下文形成有依据的判断，不依赖既往摘要。

### T-03：长期积累与修正

多会话产生补充或矛盾信息后，能保存经验和怀疑、重新检索、按证据修正或确认旧认识。用户和 Agent 写入的描述性知识适用相同纠错规则。

### T-04：无错误情况下主动探索

使用多组正常完成的任务，评价能否根据实际证据审查潜在局限或推导新能力。不强制每次发现问题，不以建议数量代替质量评估。

### T-05：完整能力进化

从建议、讨论与具体授权出发，自主验证需求、创建特殊 Skill、自主管理依赖、执行测试、通过后自动启用。新的普通会话应实际发现并调用新能力。

失败或回退不破坏上一可用版本；只生成代码、报告或文档不构成通过。

### T-06：自主权限与安全

验证日常反思能修改描述性知识，却不能未经授权修改正式 Tool、Hooks、长期规则或新建 Skill；禁用能力不能通过间接调用绕过；反思不无限自循环，不同会话状态不混淆。

模拟凭证不得明文进入受保护的持久化和外发通道，覆盖原生 Session、恢复、压缩、客户端与导出，而非仅新增日志。

安全验收还需覆盖模拟身份信息、常见凭证格式、嵌套对象、异常输出、多语言脚本及自进化开发测试日志；必要安全检查无法完成时，不得放行未经检查的数据。完整保护范围与验证要求见 [SA-07](../05-系统架构/SA-07-权限安全与能力变更边界.md#三个敏感出口)。

## 尚待验证的技术假设

Pi 生命周期语义、原生记录覆盖、动态 Tool/Hooks 管理、持久化前脱敏、多语言运行和隔离、多 Session 并发与恢复均需源码和最小实验支持。

这些是实现可行性问题，不是重新开放产品需求；四项后续验证汇总在 SA-08。数据库、前端框架、隔离与打包技术尚未选定。
