# RE-02：长期认识的形成、积累与修正

## 需求目标

支持 Agent 从跨会话实践、历史记录与已有知识中，自主形成、积累、补充、确认、修正或推翻认识。当前结论、过去判断和未经确认的怀疑应能区分，不让记忆变成只能追加的总结。

## 知识与来源

- 描述性知识统一处理，不因用户或 Agent 创建而设置不同修改权限。
- 判断可靠性依据证据与适用条件，来源用于追溯，不是权威等级。
- 怀疑、经验和能力构想允许长期保存，不要求先完成实验或人工批准。
- 未经验证的怀疑不能冒充事实；被存入 Memory 不等于已被证实。
- 知识修正保留必要来源与历史，不改写实际执行事实。

长期行为规则、Tool、Hooks 与新建 Skill 继续遵循正式授权边界；日常反思可以自主修正既有知识区域的描述性内容。

## 跨上下文与作用域

Memory 与 Skill 独立管理、按需关联。跨任务知识进入 Global/Project Memory，特定能力的理解可进入 Skill Knowledge；多个 Skill 共用的认识可以引用同一来源，避免重复副本。

上下文压缩、新会话、模型切换或长时间间隔后，相关认识仍应可发现、读取和重新理解。项目知识不能因跨项目访问而失去作用域限制；不要求全部知识常驻模型上下文。

用户回档后，废弃分支中的项目决定不再作为当前要求。通用经验是否有效应另行判断，不自动删除该分支的全部知识。

## 验收场景

1. 首次会话形成判断，后续会话获得矛盾证据，再次审查时能回溯并修正。
2. 新证据也可以支持、确认或细化此前受怀疑的认识，而非只会否定。
3. 证据不足时保留不同解释与未解决问题，不强行形成单一结论。
4. 同样的纠错能力适用于用户和 Agent 写入的描述性知识。
5. 当前知识、修改历史与证据可区分，原始 Log 不因结论变化而改变。
