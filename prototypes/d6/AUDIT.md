## 产品与用户目标

个人通用 Agent 在 Host 设备执行工作。会话是工作的持续上下文；Memory 保存跨会话认识；Reflection 审查依据与局限；建议进入讨论后，由用户批准具体能力开发目标与范围。它不修改基础模型权重，也不是团队任务管理系统。

依据：`docs/01-产品定义/01-产品定位目标与用户.md:5-23`、`DECISIONS.md:21-45`、D2–D5 验收。

## 三条旅程与信息架构

1. 创建/切换会话 → 模型及引用 → 执行 → 结果 → 失败调用 → 输入输出 → 原始证据 → 返回任务。
2. 任务变化 → 当次 Memory → 当前认识 → 历史比较 → 来源 → 修正及理由 → 新修订。项目决定撤销与通用经验保留是不同状态。
3. 建议 → 独立讨论 → 用户明确目标与 Skill 范围 → 自主开发 → Agent 自测 → Host 检查 → 自动生效 → 普通使用 → 版本回退。失败保留旧版；取消与重启不重放；允许无代码成果。

常驻：工作定位、当前状态、主要目的入口。情境出现：运行、知识变化、待决定建议。按需展开：Tool 参数、历史修订、来源标识。聚焦表面：授权和完整原文。不得恢复已取消的独立全局日志入口。

## 第一轮为什么没有通过

本轮审查目标是帮助用户完成工作、理解认识变化并作出能力授权决定。第一轮交互可执行，只能证明路径存在；不能证明阅读、判断和管理的体验成熟。原件与截图保存在 [round1](round1/)，不将旧测试结论迁移为本轮视觉结论。

| 具体问题 | 设计原则与追问 | 本轮修改 | 视觉复核位置 |
|---|---|---|---|
| A/B 共享几乎相同的主体，以外框与主题区别方向 | 如果用户用同样的顺序阅读同样的组件，方向差异在哪里？ | 重建 A 连续会话与 B 报告工作区；分别实现轨迹、Memory、能力和授权组织 | `quiet-chat-1440` / `studio-chat-1440`，以及两套 grant |

## 本轮能力边界

[UI-INVENTORY.md](UI-INVENTORY.md)逐项覆盖正式产品能力对应的 Demo 表面、状态、控件目的与实现。已有业务状态逻辑继续保留，但第一轮的页面结构不再是默认答案。Demo 没有制造“暂停后从任意 Tool 安全续跑”、额外发布审批、OS 沙箱、模型权重学习或独立任务管理实体。

设计交互补充包括搜索、对象直接入口、修订比较、代码定位、来源检查器、目录返回与焦点恢复；这些是需要用户评审的前端提案。D2 精确内容审查与 D4 目标授权仍是两类依据。人工编辑候选需要审阅具体内容；目标授权后的开发经必要检查自动生效，不能追加发布审批。

本轮不开展新的真实业务验收。正式 Web/Desktop、真实凭据与历史数据没有接入原型。浏览器结果只证明模拟路径与布局；审美与易理解程度仍需用户逐模块判断。
