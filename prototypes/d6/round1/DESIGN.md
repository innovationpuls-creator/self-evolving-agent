# 两方向设计与内容语言

## A 会话工作台

左侧会话索引，阅读区呈现用户目标和结果，输入在工作后方；记忆、反思和能力建议有明确常驻入口，相关变化在结果之后出现。证据右侧覆盖式检查器保持原阅读位置。暖中性色、有限绿色强调、开放留白与较窄阅读行宽，适合多数时间专注完成任务的用户。代价是跨会话维护要进入专门索引。

## B 工作与成长空间

顶部“工作 / 认识 / 能力”建立目的层；左侧工作目录，工作结果承载正文，相关认识、反思、改进在上下文栏直接出现。较冷的中性色、深色导航、紧凑矩形工作表面，强调对象关系及长期维护。工作仅为 Session 的展示，不新增任务实体。代价是导航层级更多；授权采用宽工作区，将讨论背景与目标范围并列；窄屏顺序展开。

## 共用内容规则

- ReactMarkdown 10.1.0 / remark-gfm 4.0.1。禁用 HTML、图片转引用文字；外链保留 noreferrer。表格及代码局部滚动。
- 代码保留语言类名，等宽与复制；没有加入自动语法高亮引擎。Diff 以新增/删除和上下文文字呈现，不仅依赖颜色。
- JSON 原字段浏览、数组数量、逐层展开；未知 Tool 不猜测业务意义。输出返回、任务成功及能力生效分开。
- 来源与完整性随证据呈现。原文分页为小型模拟分段，非真实 Host 8192字符分页实现。
- Memory 修订不可变；最新认识与引用修订分开。Reflection 的发现、不确定性、无发现均有独立呈现。
- 中文正文系统字体，UI 13/15/16/21/25 层级；正文1.65–1.8行高。色彩只服务导航、主操作及状态。动效不阻塞内容，尊重 reduced-motion。

## 参考原则

[Apple Disclosure](https://developer.apple.com/design/human-interface-guidelines/disclosure-controls)：细节靠近触发位置，常用内容先出现。不复制玻璃材质。

[Linear Triage](https://linear.app/docs/triage)：待决定事项有清晰处理入口；不引入团队分配、自动优先级或新的任务状态。

[Obsidian Reading](https://obsidian.md/help/edit-and-read)：默认可读，必要时查看原文。不建设 Markdown 编辑器。

[Zed Agent Panel](https://zed.dev/docs/ai/agent-panel)：工作线程与结果审查关联。不移植逐次 Tool 批准或发布审批。

## 用户裁决与建议

建议以 A 为日常使用基线，评审 B 的长期认识/能力可见性是否值得增加导航层级。需要裁决：会话是否为默认中心、认识与反思是否分开、相关变化常驻程度、授权侧面板还是独立工作区、阅读密度及视觉方向。本轮没有选定正式方案。
