# UX-001：反思列表的层级重复与数据依赖

状态：**待独立设计验收**。没有批准候选，没有更新视觉基线。

## 当前事实与影响

当前 `src/workspace/Reflection.tsx` 的每条记录独立放置日期与项目、符号、状态、任务标题、摘要、变更数量和箭头。它读取完整 `record`，并按 job.updated 排序。

| 问题 | 观察与影响 | 候选处理 |
| --- | --- | --- |
| 重复状态标签 | 正常记录逐条出现“检查已完成”；摘要已承担结果表达，仍先要求用户扫描状态 | 日期日志不逐条显示成功标签；分区方案在“已完成”标题声明一次 |
| 变更数量 | “已保存 N 项变更”重复占行；数量不能解释变更内容，且 summary 列表没有该数据 | 列表不显示计数，详情保留实际成果、类型与引用 |
| 冗余容器和层级 | 每行的日期列、图形列及正文内多层 span 共同制造多个起点，尤其在窄窗口 | 日期合并成组标题或并入行元信息，移除重复符号列；沿用原有分隔线与产品身份 |
| 过高行距 | 多层元信息和上下留白叠加拉高单条记录，定位异常需要更长扫描 | 合并任务标题与必要状态，压缩辅助信息层级；不压缩错误、结论正文或不确定性来凑指标 |

不以任意字数、固定行高或首屏条目数决定设计通过。浏览器记录实际行几何供观察；验收依据任务寻找、阅读顺序、必要信息可见性和实际渲染。

## 保留项

错误原因、运行和排队状态、完整详情、不确定性、已提交成果、来源标记与权限失败都必须保留。Host 不支持的列表能力不以假数据补齐。原版未满足的检查明确记为 failed / knownDefect，不降低候选断言，也不在本轮修补原版。
