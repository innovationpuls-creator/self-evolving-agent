# 第二轮逐屏视觉批评与修正

评审意图：让用户先读懂结果和当前认识，在需要时检查依据，并清楚作出能力授权决定。不是把管理能力全部隐藏，也不是让每个页面看起来一样。

本记录采用“观察 → 原则 → 追问 → 修改/复核”的顺序。视觉判断由本轮实际截图观察形成，用户拥有最终判断权；浏览器点击通过不作为审美结论。

## 从第一轮重建的基准

- **观察**：第一轮的结果、Memory、反思与能力依赖相似面板，A/B 多数内容相同。**原则**：空间结构应表达不同任务。**追问**：如果去掉标题，还能区分在阅读结论、比较历史还是批准权限吗？**修改**：重建模块表达；A 连续阅读，B 对象登记与聚焦阅读。桌面七模块截图可直接比较。
- **观察**：统一圆角、边框和浅底让普通信息都像可操作卡片。**原则**：容器应该表示关系。**追问**：这条边界表达的是选择、来源还是只是装饰？**修改**：正文用宽度、章节间距、细分隔组织；仅在编辑、结构化内容、选中、警示、浮层使用表面。保留授权范围的明确边界。
- **观察**：正文与技术字段过于接近，页标题与业务结论争夺注意。**原则**：先结论，后定位信息。**修改**：固定正文尺度和行距，元信息退后；代码以等宽、高亮、行号独立阅读。实际查看 `quiet-markdown-code.png` 与两套报告首屏。

## 逐模块复核

| 模块 | 初版观察与本轮实际修正 | 目视复核截图 | 保留的取舍 |
|---|---|---|---|
| 工作区与会话 | 目录、正文、输入之间缺少稳定关系；重建单独正文滚动与常驻输入。B 的目录在窄屏截图遮住报告，修正截图导航步骤并复查真实收起行为；认识/能力目录增加直接对象入口 | `quiet-chat-1440`、`studio-chat-1440`、`*-chat-390`、`*-session-running`、`*-session-stopped` | A 更适合持续对话；B 结果更早出现，但多一个阅读角度 |
| Markdown / 代码 | 无语言、行位置和清晰的正文节奏；加入按需语言高亮、行号、复制成功/失败、长行局部滚动与折行 | `*-markdown-code`、`*-chat-long` | B 13px正文更密，用户需判断长文舒适性 |
| 轨迹 | 第一轮像开发日志；A 变为执行叙事，B 变为调用登记。长路径折行；选择 B 记录后定位详情。成功读取的原始记录曾误复用差异调用，已拆分真实 fixture | `*-trace-1440`、`*-trace-error`、`*-trace-unknown`、`studio-trace-long`、`*-tool-error-detail-390` | B 可比较调用，A 更直观追踪顺序；技术原文仍需主动进入 |
| JSON / 取证 | 长 pre 不能区分层级；加入字段/原文、对象数量、数组、类型、逐层展开。缺失/历史/未知保持文字边界 | `*-trace-evidence`、`*-json-detail-390` | 自定义树只承诺逐级按钮浏览，不把未知结构硬转表格 |
| Memory | 当前状态被历史挤掉；建立当前认识、修订比较、依据、后续用途。B 登记册后提供返回目录；修订 Diff 真实计算，编辑冲突保留文本 | `*-memory-1440`、`*-memory-diff`、`*-memory-conflict`、`*-memory-detail-390` | A 阅读优先，B 跨对象属性比较优先 |
| Reflection | 摘要像超大标题；改成稳定结论标题、短摘要、观察、待确认、变化关联。无新发现缩为正常记录，不制造空洞大报告 | `*-reflection-1440`、`*-reflection-none`、`*-reflection-unavailable`、`*-reflection-detail-390` | 不确定性在 B 宽屏并列，在 A 连续阅读 |
| Skill / Tool | 目录承载过多细节；分离用途、文件候选、工具归属、版本信任。补齐可执行文件与保留内容一起审查。禁用状态同步工具可用性；回退恢复内容快照 | `*-skills-1440`、`*-skill-review`、`*-skill-detail-390`、`*-skill-dependencies-390` | 技术审查允许高密度，不能为了普通用户视觉而隐去本机权限 |
| Evolution | 建议、讨论与审批像同一表单；分别设计论证、讨论、具体授权和观察事件。移除授权内的演示结果选择，移到顶栏；生效 Diff 使用实际内容 | `*-evolution-1440`、`*-evolution-discussion`、`*-grant`、`*-grant-top-390`、`*-grant-bottom-390`、`*-grant-850` | A 聚焦但暂离背景；B 可留在活动工作区，但路径较长 |
| 模型与系统 | 多种授权同时展开；改成提供方状态、方式、调用检查。B 去掉重复全局侧栏，保留环境目录。保存、可用、调用成功与退出来源分开 | `*-settings-1440`、`*-settings-390`、`*-model-call-error`、`*-offline` | 没有真实提供方回调与原生窗口验证 |

文件名省略 `.png`，均位于 `evidence/round2/`。五种宽度覆盖1440、1240、850、768与390；授权另检查850×600与390上下段。每个主要模块有日常及空/加载/读取失败/长内容截图。状态页允许共用反馈语法，空内容的下一步分别指向会话、知识创建、能力导入、讨论或模型配置。

## 第二次复核中修正的细节

1. 中窗口保持三列会压缩内容，改成目录/对象切换；B 轨迹在950px以下使用单详情，Memory/能力在700px以下切换对象。
2. 中窗口授权底部不在首屏，保留对话框独立滚动，并验证能到达最后的决定按钮；权限说明在表单之前，不用 Tooltip 或折叠藏起来。
3. 选择登记对象后需要自行找正文，加入自动定位与“返回目录”；从全局搜索进入对象也能打开窄屏详情。
4. 一些辅助文字偏淡，提高 muted 颜色；正文、错误与授权说明不用最小字号。
5. 手动候选检查更新版本引用但没有恢复完整内容，补齐快照；撤回版本同时恢复说明/代码，历史仍保留。
6. 弹窗退出动画期间强制返回触发者会抢走用户新选择的输入焦点，焦点恢复改为只在没有外部新焦点时发生；重新检查 Tab 范围、Escape 返回与快速输入。
7. 实际查看代码截图后发现11.5px等宽正文偏小，将代码、JSON字段与Diff提高到12.5px，重新检查局部滚动与窄屏换行。
8. 失败活动的时间线曾把所有已记录事件画成完成勾号；改成中性事件点、末项失败叉号/生效勾号，并分开“检查结果”与“生效结果”。已授权后侧栏也改为“最近的能力活动”。
9. 生效 Diff 的前半屏曾全是未改内容，用户要滚动才看到变化；改为保留三行上下文、按需展开其余未改行，完整内容提供修改前/后各自原文。
10. 模块切换曾丢失选中内容，将页面保持挂载并按方向重置，保持页签、对象与各自滚动位置。

## 当前设计判断与待评审点

当前两方向已具备可逐模块评审的内容、结构与状态；这不是宣称已获用户验收。建议以 **A 作为日常工作中心**进入评审，重点比较 B 的跨对象登记、报告阅读与独立授权是否值得采用。不要直接拼接两套导航。

B 的登记册在宽屏更容易扫描，但目录和阅读的上下关系会增加滚动；A 的左右阅读在维护大量对象时比较效率较低。这是结构取舍，继续微调颜色不能消除。字体密度、Reflection 常驻程度、授权表面和能力目录仍需用户逐模块裁决。

尚未进行目标用户访谈、屏幕阅读器全流程验收、真实 Desktop 原生窗口与真实 OAuth/Host 业务验收。没有以自动化点击代替上述结论。
